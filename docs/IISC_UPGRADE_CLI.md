# IISC 갱신 도구

CLI의 인자 처리와 실행 진입점은 C++23 표준으로 구성한다. 같은 동작은 Qt 타입을
공개하지 않는 `File/IiscUpgrade.h`의 `upgradeIiscFile(inputPath, outputPath, limits)`로
호출할 수 있다. 경로는 UTF-8 문자열이며, 빈 출력 경로는 제자리 갱신이다.
`IiscUpgradeResult`는 오류 코드·메시지, 변경 여부, 입력 버전과 실제 출력 경로를
반환한다. 기존 iiFileProvider I/O 어댑터는 파일 모듈 내부에서 재사용하며, PSD와
타임라인 내보내기도 같은 분리된 네이티브 읽기 경계를 사용한다.

`iisc-upgrade`는 `.iisc` 바이너리 스냅샷과 SQLite 작업 파일의 문서 모델을
설치된 iiSharedCanvas가 지원하는 현재 버전으로 명시적으로 갱신하는 CLI이다.
패키지 0.31.0의 대상 모델은 IISC 1.21이며, 읽을 수 있는 기존 모델은 1.0–1.21이다.
작업 파일의 SQLite 스키마는 1로 유지된다. 확장자가 아닌 파일 헤더로 저장 형식을
구분하며, 입력의 저장 형식을 출력에도 유지한다.

```sh
# 인자 하나: 같은 파일에서 갱신한다.
~/.local/SDK/iiSharedCanvas/bin/iisc-upgrade drawing.iisc

# 인자 두 개: 원본을 보존하고 새 파일을 생성한다.
~/.local/SDK/iiSharedCanvas/bin/iisc-upgrade old.iisc new.iisc

# 대시로 시작하는 경로에는 옵션 종료 구분자를 사용한다.
~/.local/SDK/iiSharedCanvas/bin/iisc-upgrade -- '-drawing.iisc'
~/.local/SDK/iiSharedCanvas/bin/iisc-upgrade --help
```

출력 경로를 명시하면 `.iisc` 확장자를 사용해야 하며 부모 디렉터리가 이미 있어야
한다. 기존 출력 파일, 디렉터리, 심볼릭 링크는 덮어쓰지 않는다. 입력도 읽을 수 있는
일반 로컬 파일이어야 하며 심볼릭 링크는 거부한다. 인자 두 개에 같은 경로나 기존
파일의 별칭을 넣으면 출력 충돌이다. 같은 파일을 갱신하려면 인자 하나를 사용한다.

## 보존과 커밋

모든 레이어 타입과 순서, 자산 및 픽셀, 프레임 소유 키, 대지, 변환과 모션,
오디오·비디오, 생성 메타데이터, 저작자 기록을 기존 네이티브 디코더로 읽고 검증한다.
이후 `Document::formatVersion`만 현재 버전으로 바꾸고 해당 버전에 추가된 필드의
기본값을 기록한다. 레이어를 병합하거나 미리보기로 대체하지 않으며 새 저작자
이력이나 편집 시간을 만들어내지 않는다.

스냅샷의 제자리 갱신은 iiFileProvider의 비교 후 원자 교체를 사용한다. 디코딩 때
읽은 원본 바이트가 바뀌었으면 `Conflict`로 거부하며, 쓰기 실패 시 이전 파일을
유지한다. 별도 출력은 완료된 파일을 배타적으로 게시한다.

SQLite 입력은 읽기 전용 연결의 일관된 백업으로 먼저 검사하며, 커밋된 WAL 내용도
포함한다. 알 수 없는 스키마, 미래 모델 버전, 잘못된 체크섬과 참조는 원본에 쓰기
연결을 바인딩하기 전에 거부한다. 제자리 갱신은 `DocumentFile::upgradeFormat()`의
동기 트랜잭션을 사용하며, 다른 세션의 변경·잠금과 파일 교체를 기존 충돌 규칙으로
검사한다. 변경된 형식 레코드만 기록하고 기존 자산 레코드는 재사용한다. 성공한
갱신은 저장 리비전을 한 번 진행시키며 저작자 리비전은 보존한다. 현재 모델인
제자리 입력은 쓰지 않고 성공을 반환하며 파일 바이트와 리비전도 유지한다.

별도 SQLite 출력은 분리된 문서로 새 작업 파일을 생성하여 닫은 후 원자적으로
게시한다. 이 새 파일의 저장 리비전은 0에서 시작한다. 이는 소스 세션의 편집 리비전과
독립적이며, 문서의 저작자 이력은 원본 그대로이다. 원본 파일을 작업 파일과 스냅샷
사이에서 변환하는 도구는 아니다. 스냅샷은 갱신 후에도 `decodeIisc`로 읽는다.

제자리 갱신이 성공하면 구버전 표현은 새 표현으로 교체된다. 원본을 별도로
유지해야 한다면 두 번째 경로를 지정한다. 자동 백업 파일은 만들지 않는다. 갱신할
파일의 활성 편집 세션은 닫고 실행하며, 다른 세션은 갱신 후 다시 열어야 한다.
SQLite 데이터베이스를 파일 이름 교체로 덮어쓰거나 WAL·저널을 삭제하지 않는다.

## 제한과 오류

기본 `SerializationLimits`를 적용한다. 컨테이너 또는 SQLite 입력과 사이드카의
최대 크기는 1 GiB이며, 디코딩된 데이터, 픽셀, 자산, 레이어, 프레임, 문자열, 필터
수량에도 기존 네이티브 예산을 적용한다. 출력도 인코더와 작업 파일의 제한을
통과해야 한다. 제한을 초과하거나 손상된 문서는 부분 성공으로 처리하지 않는다.
실패한 새 출력과 임시 백업·스테이징 파일은 게시하지 않는다.

종료 코드는 성공·현재 버전·도움말일 때 `0`, 읽기·검증·쓰기·충돌 실패일 때 `1`,
잘못된 옵션·인자 개수·출력 확장자일 때 `2`이다. 진단은 표준 오류에, 성공 메시지와
이전/대상 버전은 표준 출력에 기록한다. 외부 코덱이나 네트워크 요청, GUI 애플리케이션,
디스플레이 또는 Qt 플랫폼 플러그인을 초기화하지 않는다. 기존 파일 제공자의 I/O
어댑터를 사용하며 새 패키지 의존성을 추가하지 않는다.

`IiscUpgradeCliTest`는 각 1.0–1.19 모델의 스냅샷·작업 파일 갱신, 전체 문서의 표준
바이트 및 렌더링 보존, 저작자 기록, 두 출력 방식, 현재 버전 무작업, 손상·미래 버전·
충돌·예산 초과·경로 별칭을 검증한다. 동일한 테스트는 설치 패키지의 실제 CLI와
공개 헤더를 사용하여 다시 실행한다. 로컬 macOS 검증은 다른 OS의 실행 증거를
대체하지 않는다.
