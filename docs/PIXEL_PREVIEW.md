# 최종 픽셀 미리보기 세션

0.34.1의 BitmapEditor와 ChunkedBitmapEditor는 외부 작성기가 계산한 최종 ARGB32
결과를 반복해서 교체할 수 있다. 하위 모듈은 도구·입력 궤적·원시 점·재생 명령을
소유하지 않는다. iiBrushTools와 같은 상위 작성기는 호출마다 결과를 계산하고
`BitmapPatch`의 빌린 표본만 동기적으로 전달한다. 공개 편집기 멤버 배치와 ABI 0.34,
정규 문서 IISC 1.22를 유지한다.

## 세션과 교체

`beginPixelPreview(label)`로 시작하고 `replacePixelPreview(patches)`에 현재 결과
전체를 전달한다. 각 갱신은 이전 갱신의 덧칠이 아니다. 새 결과에서 빠진 이전 영역은
세션 시작 픽셀로 돌아가므로 짧아진 획·테이퍼·보정된 경로가 잔상을 남기지 않는다.
ARGB32 값은 최종 합성 결과이며 alpha를 재적용하지 않는다. 좌표와 비중첩 조건은
[영역 편집](BITMAP_HISTORY.md)과 같다. 빈 배치는 현재 미리보기 전체를 원본으로
돌리고, 결과가 무변경이면 시작 전 Redo도 보존한다.

`pixelPreviewSourceAt(x,y)`는 활성 세션에서 시작 픽셀을 읽는다. 아직 건드리지 않은
위치는 현재 원본을 읽으며, 비활성 상태에서는 일반 pixelAt과 같다. 범위 밖·닫힌 파일·
바인딩 세대 불일치는 값이 없다. 상위 작성기는 이를 소스 샘플러로 사용하여 반복 계산의
피드백 혼색을 방지한다.

`commitPixelPreview()`는 현재 결과의 단일 이력 명령을 확정하고 캐시를 해제한다.
별도 픽셀 쓰기나 문서 리비전을 추가하지 않는다. 마지막 성공한 최종 결과의
채택 비용·이력 제거 수·Redo 폐기 수를 lastHistoryResult에 반환한다. 실패한 중간 갱신의
오류로 이를 대체하지 않는다. 확정 결과의 changed는 원본과 다른 최종 명령이 있는지이며
확정 호출 자체가 픽셀을 다시 썼다는 뜻은 아니다. `cancelPixelPreview()`는 원본과
시작 전 Undo/Redo를 복원한다. 활성 여부는 `pixelPreviewActive()`로 읽는다.
중첩 시작, 일반 픽셀 쓰기, 다른 브러시 시작과 사용자 Undo/Redo는 세션 중 거부한다.
파라미터 등 호출자 작성 상태는 문서 밖에서 변경하고 결과를 재계산한다.

활성 상태의 정상 바인딩은 bind/unbind로 폐기할 수 없다. 먼저 확정 또는 취소한다.
unbind는 기존 noexcept void API이므로 거부 시 바인딩을 유지하며 lastHistoryResult에
InvalidArgument를 남긴다. 이미 무효화된 파일 바인딩은 해제하거나 다시 바인딩할 수 있다.
편집기 객체 파괴 전에 세션을 명시적으로 해결할 책임은 호출자에게 있다. 소멸자에서
외부 문서 수명이나 실패 가능한 저장 작업을 추정하여 실행하지 않는다.

## 한도와 실패

원본·최종 픽셀은 64×64 타일로 보관하고 새 후보를 완전히 준비한 뒤 게시한다.
이전 갱신에서 사라진 영역도 복구를 위해 세션 종료까지 보관한다. 새 입력이 차지하는
타일의 합집합을 먼저 계산하여 픽셀 캐시 한도를 넘으면 원본·최종 타일 할당 전에 거부한다. 전체 자산 사본이나
브러시 누적 부동소수 버퍼는 만들지 않는다. previewStorageBytes는 이 픽셀 타일과
청크 존재의 논리 비용이며, 이력 커서·문자열·할당자·임시 후보·프로세스 RSS는 제외한다.

입력 크기·캐시 비용·이력 한도 초과, 중복, 무효 범위·표본 수와 외부 픽셀/기하 충돌은
이전 가시 결과·세션·커서를 보존한다. 실패한 갱신 후 재시도하거나 취소할 수 있다.
외부 변경을 덮어쓰는 취소는 Conflict로 거부하며 세션을 활성 상태로 유지한다.
기존 RasterHistoryLimits의 Reject/EvictOldest 정책은 원본 시작 커서에서 판단한다.

## 파일과 수락 경계

미리보기는 바인딩된 문서 픽셀을 실제로 바꾼다. 가시 결과가 바뀔 때 문서/저작 리비전이
증가하고 파일 바인딩에서는 동기 저장된다. 취소는 역편집으로 원본 픽셀을 복원하며
이미 기록된 저작 시각·단조 리비전을 과거로 되돌리지 않는다. 시작·동일 갱신·확정 자체는
문서를 바꾸지 않는다. 종료 전 일반 파일 닫기는 호출자 워크플로우에서 해결해야 한다.
파일이 닫힌 뒤 이전 세션의 쓰기·소스 접근을 허용하지 않는다.

이 API는 DocumentFile의 전체 임시 문서 복사·전체 자산 인코딩, 일반 구조 이력 또는
앱의 전체 Undo 순서를 교체한 것이 아니다. 실제 앱은 동결된 설치 계약을 별도 단계에서
채택한다. Native의 계약 검사, 설치 소비자와 범위별 계측을 함께 기록한다.

할당 실패 주입은 기존 가시 미리보기에서 새 결과로 교체하는 중에도 문서·캐시·커서를
검사한다. 별도 작은 예산 검사는 입력 한 픽셀이 필요한 전체 타일 캐시보다 작더라도
예산을 넘는 픽셀 버퍼를 먼저 할당하지 않는지 확인한다. 8K 검사와 독립 설치 소비자는
원본 대조·한 명령 Undo·전체 획 재계산의 교체를 검사한다.
