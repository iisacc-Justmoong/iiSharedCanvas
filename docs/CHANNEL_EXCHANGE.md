# 채널 연산과 교환 명세

상태: 아래 범위는 네이티브 C++와 Python에서 제공한다. 현재 저장 형식은 IISC 1.29,
패키지 ABI는 0.40으로 유지한다. 이 채널 기능 자체는 문서 모델이나 파일 형식을 추가하지 않는다.

## 공통 계약

각 실행 객체는 명시적으로 제공된 값만 읽고 소유된 결과 또는 오류를 반환한다.
문서 선택, 프레임 렌더링, 결과 게시, 이력과 파일 접근은 외부 제어기가 담당한다.
원본 값은 수정하지 않으며 유효하지 않은 입력과 예산 초과는 부분 결과를 반환하지 않는다.
모든 커버리지는 0–255이며 래스터는 직선 알파의 8비트 ARGB이다. 색 프로필 변환은
수행하지 않는다. 실행 객체는 동기적으로 동작하며 호출자가 같은 입력에 대한 동시 쓰기를 막는다.
두 CMake 구성은 공통 숫자 표현에 `iiSDKCore::Contracts`를 명시적으로 사용하며,
네이티브 구성에 새로운 Qt 의존성을 추가하지 않는다.

## 선택 프레임과 병합 프레임

`SelectedFrameComposite`는 호출자가 미리 렌더링한 한 프레임의 레이어 배치와
고유한 선택 레이어 ID를 받는다. 선택된 가시 아트워크만 원래의 쌓인 순서와
그룹 합성 규칙으로 투명한 배경에 합성한다. 아트보드의 배경색은 포함하지 않지만
선택한 레이어의 아트보드 경계는 유지한다. 클리핑된 선택 레이어의 원래 기준
레이어가 선택에 없으면 조용히 다른 기준을 사용하지 않고 오류를 반환한다.

`MergedFrameComposite`는 같은 배치의 모든 가시 아트워크와 아트보드 배경을
기존 합성 규칙대로 처리한다. 두 연산은 선택적으로 출력 타일과 같은 크기의
8비트 선택 커버리지를 적용하며, 알파에 커버리지를 곱한다. 선택 커버리지가
없으면 전체 결과를 보존한다. C++ 호출자는 외부 렌더링 단계에서 프레임과 타일
영역을 지정한다. Python은 `frame`을 생략하면 0을 사용하며 UI의 현재 프레임이나
레이어 선택을 읽지 않는다.
기본 예산은 64M 픽셀이다. 병합 결과는 모든 요청의 출력 픽셀 수를 합산하고,
선택 결과는 이 합에 선택 레이어 수와 출력 사본 하나를 곱해 검사한다. 합성
라이브러리의 중간 버퍼와 호출자가 보유한 원본 배치는 이 논리 예산에 포함되지 않는다.

## 채널 연산

호출자가 원본 문서, 프레임, 레이어와 좌표계를 선택하고 렌더링해 같은 크기의
직선 알파 ARGB 픽셀을 제공한다. `ApplyImageComposite`는 소스의 RGB 전체 또는
적색·녹색·청색·알파·휘도를 대상 이미지의 RGB 전체나 한 채널에 혼합한다.
반전, 혼합 모드, 불투명도와 선택 커버리지는 명시적이다. 선택 바깥은 대상과
동일하다. 단일 채널 연산은 해당 성분만 변경하며 나머지 성분을 보존한다.
결과 픽셀은 분리된 값이다. 외부 제어기가 대상 레이어·프레임의 원본과 락을
확인하고 `DocumentHistory::replaceLayerFrameRaster`로 게시하면 하나의 Undo/Redo가
된다. 다른 프레임·레이어와 자산을 공유하는 경우 새 자산을 소유하며 선택 프레임의
참조만 바꾼다. 유지 노출에 중간 프레임이 있으면 다음 프레임의 원래 노출을 복원한다.
정적 레이어를 일부 프레임만 바꿔야 하면 동적 레이어로 바꾸되 다른 프레임의 픽셀과
레이어 속성을 보존한다. 계산에 사용한 원본 픽셀 전체와 리비전을 현재 값과 정확히
비교해 이력 밖의 변경을 감지한다. Undo/Redo도 보존한 원본 자산의 내용이 다르면
충돌로 중단한다. 원본과 결과의 이력 저장량, 픽셀·투명도·구조 잠금과 이력 예산도
게시 전에 검사한다. 더 이상 참조되지 않는 원본 자산은 자동 삭제하지 않는다.

`ChannelCalculations`는 두 원본의 단일 채널을 추출하고 각각 반전할 수 있다.
첫 채널을 둘째 채널 위에 혼합한 8비트 회색 커버리지를 반환하며, 결과 반전과
선택 커버리지를 지원한다. 선택이 부분적이면 둘째 채널에서 혼합 결과까지
보간한다. 결과는 독립적이며 외부 제어기가 현재 선택으로 사용하거나 문서의
이름 있는 선택 채널로 저장하거나 새 문서를 만들 수 있다. 크기가 다른 입력은
호출자가 먼저 정렬해야 한다. 비유한 불투명도, 잘못된 채널·마스크, 지원되지
않는 혼합과 예산 초과는 원본을 수정하지 않고 오류를 반환한다.
휘도는 인코딩된 RGB에 Rec. 709 계수 0.2126, 0.7152, 0.0722를 적용해 반올림한다.
전체 RGB 소스를 한 대상 채널에 적용할 때도 이 휘도를 쓴다. 채널 추출은 알파 0의
숨겨진 RGB도 읽으며 전체 RGB 소스의 경우 소스 알파를 합성에 사용한다. 단일 채널은
제거와 색상·채도·색상 혼합·명도 같은 비분리 혼합을 거부한다. 전체 RGB 합성은
기존 iiPaintEngine 혼합 모드와 알파 규칙을 사용한다.

## CSS와 SVG 출력

`LayerCssEncoder`는 명시적으로 전달된 레이어 속성과 콘텐츠로 CSS 선언을
반환하며 변환할 수 없는 마스크·효과·합성 관계는 손실 항목으로 알린다.
`SelectedLayerSvgProjection`은 표현 가능한 벡터를 SVG 경로로 유지하고 정확히
표현할 수 없는 선택 결과는 호출자가 준비한 합성 픽셀을 내장 이미지로 사용한다.
외부 파일 경로나 네트워크 참조 없이 자체 완결된 결과를 만든다. SVG 벡터 보존
여부와 CSS 표현 손실은 결과에서 확인할 수 있다.

CSS 선언은 크기, 위치, 정적 변환, 불투명도, 가시성 및 단색 채우기를 포함한다.
지원하는 CSS 혼합 모드는 출력하되 주변 스태킹 문맥에 따른 차이를 손실 목록에
표시한다. 그라디언트·패턴 콘텐츠, 마스크, 필터, 스타일, 클리핑, 조건부 혼합,
아트보드와 모션은 현재 CSS에 완전히 투영하지 않으며 해당 손실을 반환한다.
콘텐츠를 전달하지 않은 경우에도 이를 알린다.
문서에 속한 레이어는 그룹 트리도 전달해야 상위 그룹의 가시성과 합성 영향을
손실 목록에 반영할 수 있다. Python 문서 제어기는 그룹 트리를 자동으로 전달한다.

SVG 벡터 경로는 효과·마스크·타임라인·그룹·아트보드나 배경 의존 혼합이 없는
정적 벡터 레이어에서 유지한다. 독립적으로 합성할 수 있는 래스터·마스크·효과·모션과
정확한 부울 복합 도형은 해당 레이어만 PNG로 내장하고 나머지 벡터 경로와 쌓인 순서를
유지한다. 클리핑, 조정 레이어, 배경 의존 혼합, 그룹이나 아트보드 등으로 독립적인
분리가 결과를 바꾸는 경우에는 선택 합성 전체를 PNG로 내장한다. 래스터화된 레이어와
편집성 손실은 결과에 명시한다. C++ 호출자는 같은 프레임·레이어·문서 영역에 맞춘
레이어별 픽셀과 필요할 경우 전체 선택 합성을 제공할 책임이 있다. 개별 픽셀이 없으면
전체 합성으로 대체하며, 필요한 픽셀이 없거나 크기가 다르면 오류가 난다. Python
제어기는 기존 레이어 배치를 이용해 필요한 합성 픽셀을 준비한다. SVG 뷰박스는 문서
좌표이며 표시 크기에 문서 픽셀 종횡비를 반영한다.

## API와 검증

C++에서는 `<iiSharedCanvas>`의 여섯 실행 객체를 사용한다. Python의
`CanvasDocument.composite`, `apply_image`, `layer_css`, `selected_layers_svg`와
`calculate_channels`가 대응한다. Python `apply_image`는 대상 레이어와 프레임을
받으며 유한 래스터 자산과 입력 크기가 같아야 한다. 다른 문서의 프레임은 해당
문서의 `composite`로 먼저 얻는다. 계산 결과는 `save_selection`에 전달해 이름 있는
채널로 저장하거나 `CanvasDocument.from_channel`로 새 회색조 문서를 만들 수 있다.
Python 브리지는 요청당 최대 16M 픽셀을 받아들이며 결과를 파일이나 클립보드에 자동으로
게시하지 않는다. 입력 소유권, 프레임과 좌표, 선택 마스크, 오류, 문서 변경과
Undo/Redo의 경계를 테스트로 검증한다.
