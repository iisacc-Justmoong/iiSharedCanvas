# 비트맵 편집기의 실제 입력 경계

iiSharedCanvas 0.33.0은 `BitmapEditor`와 `ChunkedBitmapEditor`에 현재 `StrokePoint` 하나를 받는 `beginStrokeInput`·`continueStrokeInput`·`endStrokeInput`을 제공한다. 정확한 `StrokePoint` 타입에는 같은 이름의 `beginStroke`·`continueStroke`·`endStroke` 템플릿도 사용할 수 있다. 기존 `beginStroke({x,y},pressure)`와 압력을 생략한 중괄호 호출은 모호해지지 않는다.

```cpp
StrokePoint sample;
sample.position = {32, 24};
sample.pressure = .7;
sample.time = 123.45; // 앱이 관측한 단조 시간, 초
sample.tiltX = .4;   // 정규화된 펜 기울기
sample.rotationRadians = .5;
editor.beginStrokeInput(sample);
sample.position.x += 4;
sample.time += .02;
editor.endStrokeInput(sample);
```

## 값과 수명

- 좌표는 문서 픽셀이고 각 축의 절댓값은 1e9 이하이다. 압력은 0..1, 기울기와 tangential pressure는 −1..1, 회전은 라디안이다.
- 시각은 초이며 절댓값 1e12 이하의 유한 값이다. 활성 획 안에서는 감소할 수 없다. 같은 시각의 표본은 허용한다.
- velocity·arcLength는 유한한 음수가 아닌 값이고 custom 8개 채널도 유한해야 한다. 스트리밍 엔진은 후속 점의 속도·누적 거리를 실제 위치·시각으로 계산한다.
- 현재 입력의 pressure·time·tilt·rotation·tangential pressure·custom·deviceState를 엔진에 전달한다. 장치 종류·포인터 캡처·장치 전환 시 취소는 호출자의 입력 정책이다. `deviceState`는 상태 비트이며 영속적인 물리 장치 ID가 아니다.
- 입력 궤적, 표본 목록, dab 목록은 저장하지 않는다. 스트림은 직전 현재 점과 스칼라 상태만 유지하고, 문서 및 IISC에는 결과 픽셀만 남긴다.
- 좌표·압력만 받는 기존 호출은 호환성을 위해 이벤트마다 1/120초를 합성한다. 실제 입력으로 이관하는 소비자는 새 경계를 사용해야 한다. 기존 호출의 보존은 실제 시각 지원을 의미하지 않는다.

## 획 합성

입력 이벤트마다 별개의 획처럼 합성하면 작은 alpha 양자화 오차가 누적되고 획의 불투명도 상한도 다시 적용된다. 런타임은 처음 건드린 64×64 타일의 원본 픽셀과 premultiplied 누적 커버리지를 유지하여, 새 표본이 바꾼 픽셀만 원본 위에 다시 합성한다. 소스 오버와 지우개는 iiPaintEngine의 기존 픽셀 합성 함수를 사용한다. 나머지 혼합 모드는 같은 원본과 누적 색을 해당 혼합 모드로 계산한다.

캐시는 캔버스 전체 크기가 아니라 건드린 타일에 비례한다. 음수 좌표 타일과 무한 캔버스 청크 경계를 구분한다. 파일 편집은 캐시와 타일의 copy-on-write로 실패한 트랜잭션이 원래 런타임 상태를 바꾸지 않게 한다. 종료·취소·바인딩 변경은 캐시를 폐기한다. 취소와 Undo/Redo는 기존 픽셀 이력을 사용한다. 전체 자산 스냅샷 이력과 파일 트랜잭션의 비용을 이 변경만으로 해결했다고 해석하지 않는다.

입력 표본을 타일별로 나눌 때 각 타일의 표본 수를 먼저 세어 필요한 공간을 한
번 예약한다. 같은 타일 안의 원래 표본 순서는 유지한다. 획의 원본 타일은
불변으로 공유하고, 새 미리보기와 누적 커버리지는 독립적으로 준비한 뒤에만
게시한다. 따라서 계속 그릴 때 원본 픽셀 버퍼를 반복 복제하지 않으면서 실패한
준비가 기존 획을 바꾸지 않는다. `StrokeCompositeBatch`는 반복·음수 좌표와
여러 타일의 소스 오버, 지우개, 혼합 결과 및 일반 C++ 할당 요청을 검사한다.

하나의 편집기에는 호출자가 순서대로 입력을 전달한다. 이 캐시는 병렬 호출을 동기화하는 수단이 아니다.

## 외부 이력 관리 획의 실시간 미리보기

0.35.38부터 자체 문서 이력과 독점 소유권을 가진 호출자는 메모리 `Document`에 바인딩한
`BitmapEditor` 또는 `ChunkedBitmapEditor`에 `setExternalStrokeHistory(true)`를
지정할 수 있다. 이 모드는 입력마다 새로 바뀐 타일만 합성하여 문서에 반영하며,
입력 지점·필압·기울기·시각과 누적 합성 결과는 기존 브러시 엔진과 같다.
획 취소는 획 전 픽셀과 청크 존재 상태를 복원한다. 호출자는 활성 획 동안 해당
자산을 독점해야 하고, 같은 타일에서 충돌이 확인되면 입력은 거절된다.

이 모드는 내부 Undo 항목을 만들지 않으므로 호출자가 획 전체의 Undo/Redo를
관리해야 한다. 변경된 획을 확정하면 이전 내부 이력은 무효화된다. 취소와
변경 없는 획은 기존 내부 이력을 보존한다. 활성 획, 픽셀 미리보기, 파일
바인딩 또는 자동 캔버스 확장 중에는 설정할 수 없다. 기본값은 기존 내부 이력
모드이며, 파일 트랜잭션과 다른 편집기의 기존 동작은 바꾸지 않는다.

`setDeferredStrokeHistory(true)`는 같은 즉시 타일 합성을 사용하면서 내부 이력을
횟수마다 다시 만들지 않고 놓을 때 획 전체를 하나의 Undo 항목으로 만든다. 이력
예산은 확정 시 검사한다. 예산 또는 충돌로 확정이 거절되면 미리보기와 활성 획을
보존하며 호출자는 취소해 원래 픽셀로 복원할 수 있다. 이 모드도 메모리 문서의
독점 소유권이 필요하고 파일 바인딩·자동 캔버스 확장과 함께 사용할 수 없다.

## 투영된 픽셀과 교체 가능한 획 끝

메모리 문서를 독점하고 외부 또는 지연 이력을 설정한 호출자는
`beginProjectedStroke`, `updateProjectedStroke`, `endProjectedStroke`로 이미
래스터화한 표본을 전달할 수 있다. 업데이트의 첫 표본 묶음은 기존 획에 누적하고,
두 번째 묶음은 현재 획 끝에 대한 일시적인 픽셀 합성으로 표시한다. 다음 갱신은
이전 끝의 타일만 복원하고 새 끝으로 교체한다. `strokeSourceAt`은 임시 픽셀이
아닌 획 시작 전 픽셀을 제공한다. 투영 결과는 기존 획의 누적 불투명도와 혼합
순서를 공유하며 문서는 표본 좌표나 자국 명령을 보관하지 않는다.

종료는 화면에 이미 표시된 임시 타일을 그대로 이력에 편입한다. 별도의 전체 획
재생은 하지 않는다. 취소는 확정 부분과 임시 부분 모두를 되돌린다. 지연 이력은
한 획을 하나의 Undo 항목으로 만들며, 예산 초과나 게시 실패 시 기존 복구 계약을
따른다. 이 경로는 경계가 정해진 래스터와 청크 자산을 지원하고 파일 바인딩 및
자동 캔버스 확장은 지원하지 않는다. 호출자는 브러시 계산, 일시 구간의 수명,
표본 검증과 기기 입력을 담당한다. 편집기의 객체 배치가 바뀌므로 소비자는 새
헤더와 라이브러리로 함께 다시 빌드해야 한다. 문서 형식은 바뀌지 않는다.

`ProjectedStrokeTest`는 유한 래스터와 청크에 대해 임시 픽셀의 교체·겹침·원본
조회, 잘못된 좌표 거부, 취소, 최종 픽셀 보존과 Undo/Redo를 검사한다. 이 검사는
장치 화면의 표시 지연을 측정하지 않는다.

## Python에서 투영 픽셀 사용

선택적으로 빌드하는 `iiSharedCanvasPython`은 Python 3.9 이상에서 표준 라이브러리만
사용하는 `iisharedcanvas` 모듈을 제공한다. 네이티브 호스트 빌드에서는
`IISHAREDCANVAS_BUILD_PYTHON_API=ON`이 기본값이며 `OFF`로 비활성화할 수 있다.
설치된 모듈은 SDK 접두 경로의
`share/iiSharedCanvasNative/python`에 있다. 해당 경로를 `PYTHONPATH`에 추가하거나
모듈 검색 경로에 넣어 가져온다. 브리지 라이브러리의 경로는 자동으로 찾으며,
필요하면 `ProjectedRaster(..., library=경로)` 또는 환경 변수
`IISHAREDCANVAS_PYTHON_LIBRARY`로 명시할 수 있다.

```python
from iisharedcanvas import ProjectedRaster, RasterSample

with ProjectedRaster(256, 256) as raster:
    raster.begin_stroke()
    raster.update_stroke([RasterSample(8, 8, 0xff6633ff)], [])
    raster.update_stroke([], [RasterSample(9, 8, 0xff6633ff)])
    shown = raster.pixel(9, 8)
    raster.end_stroke()
    assert raster.pixel(9, 8) == shown
    raster.undo()
    raster.redo()
```

이 인터페이스는 유한 메모리 래스터에 이미 투영된 ARGB 표본을 전달하는 범위이며
브러시 자국 생성이나 문서 파일 편집 API를 대신하지 않는다. 배경색과 지우개
혼합을 선택할 수 있고 픽셀 및 획 시작 전 소스를 조회할 수 있다. 크기와 입력은
SDK의 메모리 예산을 따르며, 실패는 Python 예외로 전달한다. 객체는 단독 소유하며
복사하거나 여러 스레드에서 동시에 호출하지 않는다. 독립 C ABI 헤더도 함께
설치된다. 이 호스트용 브리지는 iPad 앱에 링크되지 않으며 앱이 Python 실행기나
바이트코드를 필요로 하지 않는다.

`ProjectedStrokePythonTest`는 브리지의 픽셀 교체, 원본 조회, 지우개, 잘못된 입력,
복사 방지, 취소, 변경 없는 획의 Redo 보존과 Undo/Redo를 확인한다.

비유한 입력·역행 시각·엔진 이벤트 예산 초과는 `false`와 `lastError()`로 보고한다. 입력 값/예산 거부는 픽셀·리비전·활성 획을 보존하며, 정상 입력으로 계속하거나 취소할 수 있다. 시스템 메모리 고갈 전체에 대한 무실패 보장은 아니다.

## ABI와 검증 범위

0.33.2의 `advanceStrokeTime`과 `rebaseStrokeTime`은 입력 이벤트 사이의 실제 시각과 중단·복귀를 처리한다. [획 시계 계약](BITMAP_CLOCK.md)을 참조한다.

편집기 런타임 객체의 배치가 바뀌므로 0.33으로 소비자를 재빌드해야 한다. 문서 타입과 IISC 1.22 형식은 바뀌지 않는다. 현재 Native 패키지는 iiPaintEngine 0.5.3 이상을 사용한다.

`BitmapInputTest`는 유한·청크 편집기에서 펜 회전·기울기의 실제 자국, custom 채널, 실제 경과 시간과 이벤트 빈도, 잘못된 입력·예산 거부, 취소·Undo/Redo 및 기존 중괄호 API를 검증한다. 파일에 바인딩한 양쪽 편집기도 입력 거부 시 저장 리비전 보존, Undo/Redo, 닫기·재열기 후 픽셀 보존을 검사한다. 설치 소비자도 설치 헤더와 라이브러리로 같은 공개 동작을 검사한다. 물리 펜, 앱 어댑터의 값 전달, 정지 상태에서 호출하는 앱 시계는 별도 채택 단계이다.

입력 회귀 검사는 유한 메모리·청크 메모리·청크 경계·유한 파일 왕복·청크 파일 왕복의
각 구간에서 `BITMAP_INPUT_STAGE` 벽시각을 출력한다. 기능 기대값과 기존 시간 제한을
유지하면서 어느 구간에서 지연 또는 시간 초과가 발생하는지 검증 기록으로 남긴다.

정상 종료한 획은 마지막 성공한 미리보기의 채택 결과를 보고한다. 거부된 입력 뒤
커버리지 없는 끝 표본으로 정상 종료해도 과거의 실패 코드를 성공 결과에 남기지 않는다.


## 청크 획 재생 상태

문서에 직접 바인딩된 `ChunkedBitmapEditor`의 활성 획에서는
`currentStrokeBrushState()`가 해당 획의 유효한 브러시 설정과 시드를 반환한다.
획이 없거나 파일 바인딩 편집기의 임시 트랜잭션에서는 빈 값을 반환한다.
호출자는 획 종료 전에 상태를 얻어야 하며 원본 타일과 입력 표본 보존,
재생의 메모리 예산 및 결과 적용은 호출자가 담당한다.
