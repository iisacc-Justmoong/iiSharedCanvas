# 비트맵 영역 편집과 이력

0.34.0의 BitmapEditor와 ChunkedBitmapEditor는 iiPaintEngine 0.5.4의
RasterEditHistory와 할당 실패를 보강한 iiFileProvider Native 0.10.1 이상을 사용한다. 공개 객체 배치가 바뀌므로 소비자를 재빌드해야 한다.
IISC 정규 문서 형식은 1.22 그대로이다.

## 편집 단위와 좌표

`BitmapPatch`는 row-major 최종 ARGB32 표본의 빌린 span이다.
`replacePatches(span)`의 여러 비중첩 사각형을 한 명령으로 적용하고 한 번에 Undo한다.
유한 자산은 자산 로컬 좌표, 청크 자산은 할당된 무한 캔버스 영역의 세계 좌표이다.
크기·표본 수·범위·중복을 거부하면 픽셀·문서 저작 리비전·편집기 리비전과 커서를 보존한다.
입력은 동기 호출 동안만 빌리며 문서에는 남기지 않는다.

기존 setPixel·replacePatch·clear·replacePixels·replaceRegion도 같은 저널을 사용한다.
유한 자산의 크기와 청크의 존재 여부는 픽셀과 같은 명령에 기록한다.
Undo는 새로 할당한 청크를 제거하고 clear Undo는 원래 있던 0색 청크까지 복원한다.
레이어 그룹·자산 삽입/삭제 등 일반 구조 명령의 이력은 별도 후속 범위이다.

## 한도와 오류

생성자의 `RasterHistoryLimits`가 바이트·항목·패치·입력 한도를 정한다.
기본은 64 MiB·32개이며 초과 시 적용 전에 Reject한다. 명시적으로 EvictOldest를
선택하면 제거한 항목 수를 `lastHistoryResult().evictedEntries`로 확인한다.
무변경 편집은 리비전·Redo를 바꾸지 않는다. 단일 명령 자체가 한도를 넘으면 기존 이력을
제거하지 않는다. `historyStatistics()`는 확정 또는 활성 미리보기 커서의 논리 보관량이다.

이 통계는 소스 문서·할당자·임시 계획·파일 임시 문서의 메모리를 포함하지 않는다.
브러시의 원본/누적/최종 픽셀 타일은 `previewStorageBytes()`로 별도 확인한다.
활성 획은 취소 시 기존 Undo/Redo를 복원하기 위해 이전 불변 커서도 보유한다.
따라서 활성 중 실제 메모리는 현재 커서 통계 하나만으로 판단하면 안 된다.

## 미리보기와 현재 입력

브러시는 현재 StrokePoint와 스칼라 dab 상태만 유지한다. 전체 원본 자산 대신 건드린
64×64 픽셀 타일의 원본·부동소수 누적·최종 미리보기를 보관한다.
매 입력의 후보는 같은 획 시작 픽셀에서 다시 이력 예산을 판정한 뒤 게시한다.
거부된 입력은 이전 미리보기·시각·활성 획을 보존하며, 입력 궤적·dab 목록은 저장하지 않는다.
끝내기는 한 명령을 확정하고 취소는 픽셀과 이전 커서를 복원한다.
이 미리보기는 기존 스트리밍 브러시 경로이다. 0.34.1은 iiBrushTools 등 외부 작성기의
전체 결과를 교체하는 별도 [최종 픽셀 세션](PIXEL_PREVIEW.md)도 제공한다.
혼색 샘플러는 원본 타일이 있으면 이를 읽고 아직 건드리지 않은 위치는 현재 자산을 읽는다.

## 파일과 바인딩

파일 바인딩은 DocumentFile의 동기 트랜잭션 안에서 픽셀과 작업 커서를 준비하고,
저장이 성공한 뒤에만 호출 편집기에 커서를 설치한다. 파일이 닫히거나 바인딩 세대가
바뀌면 이전 편집기를 거부한다. 같은 소스의 외부 편집과 Undo 충돌을 검사한다.

Native 0.35.1의 같은 크기 픽셀 편집은 준비된 변경 영역을 파일의 타일 트랜잭션에 직접
연결한다. 자세한 원자성·자원 한도·호환성은 [파일 영역 저장](BITMAP_FILE_REGIONS.md)을
참조한다. 일반 `DocumentFile::edit`, 크기 변경과 이전 모델의 갱신은 여전히 전체 임시
문서를 사용한다. 일반 구조 delta, 앱 이력 통합과 실제 대형 필터/마스크 워크플로우
수락은 D28의 후속 단계이다.

## 수락 검사

`BitmapHistoryTest`는 다중 영역·무변경·잘못된 두 번째 영역·중복·명시적 한도와 제거,
유한 크기 변경·음수 청크 경계·청크 존재 복원·미리보기 거부/취소·파일 왕복을 검사한다.
별도 8K 검사는 실제 Native 편집기의 고엔트로피 래스터 3개(768 MiB), 비중첩 영역
48개와 브러시 미리보기 취소, 참조된 래스터 마스크의 편집·Undo를 실행한다. 초기 표본을
재생성하여 세 자산의 모든 픽셀이 복원되는지 검사하며 추가 전체 자산 사본은 보관하지 않는다.
`operations_ms`는 준비·전체 표본 대조를 제외한 해당 동기 편집 호출 구간이다. 실제 필터
합성·파일 저장·프로세스 RSS 또는 최종 대형 문서 워크플로우 수락과 구분한다.
전체 빌드·기존 입력/혼색/시계 검사·설치 소비자와 검사 범위별 계측을 함께 기록한다.
