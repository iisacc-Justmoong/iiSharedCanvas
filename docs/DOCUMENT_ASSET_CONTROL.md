# 문서 자산과 이력 제어 명세

이 문서는 Native 0.36.0에서 구현한 연결 캔버스, 문서 정보와 최근 래스터 편집의 공통 계약이다.
제품별 화면, 파일 선택기와 명령 단축키는 소비자가 소유한다.

## 소유한 연결 캔버스

`LinkedCanvasAsset`은 다른 캔버스 문서의 독립적인 복사본을 상위 문서 안에
소유한다. 원본 경로, 외부 파일 핸들이나 원본 문서의 수명에 의존하지 않는다.
한 자산을 여러 레이어에서 참조하면 이들은 같은 내장 복사본을 사용한다.
복사본을 교체하면 그 자산을 참조하는 모든 레이어에 새 내용이 적용된다.
상위 문서의 저장·재개방 및 이동 후에도 복사본과 참조를 보존한다.
원본을 나중에 수정하거나 삭제해도 이미 복사한 내용은 바뀌지 않는다.

`LinkedAssetResolver::copy`는 대상 `Document`를 정규 IISC 바이트로 복사하고
표시할 자식 프레임을 지정한다. `DocumentEditor::insertLinkedCanvasAsset`과
`replaceLinkedCanvasAsset`은 각각 자산을 추가하거나 동일 ID의 복사본을
교체한다. 이력에 포함하려면 `DocumentHistory::insertLayerWithAsset` 또는
`replaceLinkedCanvasAsset`을 사용한다. 결합 삭제는 다른 레이어가 같은 자산을
참조하는 경우 충돌을 반환한다. 정적·동적 비트맵 레이어가 자산 ID를 참조한다.

`LinkedAssetResolver`는 내장 문서의 지정된 프레임을 검증하고 렌더링한다.
결과는 분리된 픽셀이며 원본이나 상위 문서를 수정하지 않는다. 중첩 문서,
입력 크기와 디코딩에는 명시적인 제한이 적용된다. 잘못된 데이터, 지원하지
않는 버전, 프레임 범위 오류와 제한 초과는 빈 이미지로 숨기지 않고 반환한다.
소스 캔버스의 원점과 크기는 결과에 포함하며, 상위 레이어의 변환·불투명도와
합성 순서는 기존 렌더링 계약을 따른다.

기본 제한은 내장 깊이 16단계와 직접 소유 바이트 합계 1 GiB이다. 더 안쪽의
바이트는 이미 바깥 복사본에 포함된다. 모든 내장 단계에서 아트보드를 합친
출력 뷰 크기에도 호출자의 캔버스 픽셀 한도가 적용된다. `validate`는 자산 형상만 검사하며, `encodeIisc`, `decodeIisc`,
작업 파일 디코딩과 resolver는 내장 컨테이너의 체크섬·구조·프레임을 재귀적으로
검사한다. 현재 연결 자산 자체를 마스크나 필터 소스로 사용하는 것은 지원하지
않는다. PSD 및 타임라인 교환은 내장 문서를 보존할 수 없어 명시적으로 거부한다.

내장 자산은 새 형식 버전으로 저장한다. 이전 형식은 계속 읽으며, 이전
리더는 새 자산을 모르는 상태에서 내용을 삭제하거나 평면화하지 않고 거절해야
한다. 작업 파일의 갱신과 자산 교체 실패는 이전 문서와 리비전을 보존한다.
이 기능이 도입된 형식은 1.23이다. 현재 문서 형식은 1.29이며 패키지 ABI는 0.40이다. 이전 소비자는 새 헤더와 라이브러리로
다시 빌드해야 한다. 작업 파일 내부 저장 스키마는 기존 버전 2를 유지한다.

## 문서 정보 스냅샷

`DocumentInfoSnapshotBuilder`는 문서의 형식·캔버스·타임라인·레이어·자산과
선택적인 파일 및 이력 정보를 소유된 값으로 수집한다. 스냅샷은 원본 픽셀이나
내장 문서 전체를 복사하지 않고, 이후 원본 편집이나 소멸의 영향을 받지 않는다.
문서 저작 리비전과 작업 파일 저장 리비전은 별도로 표시한다. 정보 조회는
저장·저작 정보 변경·Undo 항목을 만들지 않는다. 문서와 이력의 스레드 수명
계약은 기존 소유자의 계약을 따른다.
연결 자산의 선택 프레임과 보유 바이트 수, 작업 파일 경로와 저장 버전도
스냅샷에서 확인할 수 있다. 파일 경로는 정보이며 자산 연결에 사용하지 않는다.

## 마지막 편집 토글

`LastEditToggle`은 명시적으로 선택한 마지막 이력 항목의 적용 전후를 Undo와
Redo로 전환한다. 항목의 안정적인 식별자를 확인해 다른 명령을 대신 되돌리지
않는다. 새로운 편집, 이력 재설정, 외부 변경, 활성 미리보기 또는 닫힌 파일로
대상 항목을 안전하게 전환할 수 없으면 실패를 반환하고 커서를 보존한다.
실패한 Undo/Redo의 파일 및 이력 원자성은 `DocumentHistory` 계약과 같다.

## 다시 편집할 수 있는 래스터 변경

`ReeditableRasterChange`는 선택한 유한 래스터의 원본 픽셀을 소유하고
색상 조정 또는 래스터 효과의 설정을 변경할 때마다 그 원본을 기준으로 새
결과를 계산한다. 이전 결과 위에 같은 효과를 누적하지 않는다. 각 확정은 기존
`DocumentHistory`의 한 항목이며 Undo와 Redo에 참여한다. 대상 픽셀이나 문서가
세션 밖에서 변경되면 덮어쓰지 않고 충돌을 반환한다. 계산 실패, 잘못된 설정,
저장 실패 및 이력 예산 초과는 기존 픽셀과 이력을 보존한다.

원본과 결과를 보관하는 메모리의 상한은 호출자가 지정할 수 있다. 이 세션과
Undo/Redo 이력은 현재 문서 편집 세션의 상태이며 파일을 다시 열 때 자동으로
복구된다고 가정하지 않는다. 브러시 입력 궤적과 재생 명령은 저장하지 않는다.
`settings()`는 마지막으로 성공한 조정 또는 효과 설정을 돌려준다.
예산은 원본·직전 결과·다음 결과에 필요한 세 개의 ARGB 픽셀 버퍼를 기준으로
검사한다. 래스터 처리 내부 임시 할당과 이력 저장은 각각의 기존 예산을 따른다.

## Python 사용

선택적 `IISHAREDCANVAS_BUILD_PYTHON_API` 빌드의 `CanvasDocument`는 래스터
문서 생성과 IISC 바이트 읽기·쓰기, `embed`, `replace_linked`, `snapshot`,
`capture_last_edit`/`toggle_last_edit`, `begin_reeditable`과
`reedit_adjustment`/`reedit_effect`를 제공한다. 설정 키는 C++ `ColorAdjustment`,
`RasterEffect` 필드명이며 effect 종류는 `RasterEffectKind` 선언 순서의 정수이다.
핸들은 단일 스레드 전용이며 `with` 문 또는 `close()`로 해제한다.

## 검증 범위

계약 검사는 내장 복사·공유·교체·직렬화 왕복, 중첩 및 손상 거부, 분리된
정보 스냅샷, 마지막 항목 식별·분기 충돌, 원본 기준 재계산과 예산·실패 보존을
포함한다. 파일 바인딩은 작업 파일의 저장 및 재개방을 별도로 검사한다.
할당 실패 주입은 현재 iiSharedCanvas의 삽입·교체·롤백을 검사한다. macOS에서
설치된 iiFileProvider의 `Authorship::fromDump` 정규식 내부에 실패를 주입하면
접근 오류가 발생해 그 내부 할당 지점은 주입 대상에서 제외한다. 이 결과는 해당
하위 디코더의 할당 실패 안전성을 입증하지 않는다.
