# 획 시계와 중단 시간

iiSharedCanvas 0.33.2는 유한·청크 편집기에 `advanceStrokeTime(seconds)`와 `rebaseStrokeTime(seconds)`를 제공한다. 시계는 호출자가 소유한다. SDK는 타이머·스레드·GUI 이벤트 루프를 만들지 않는다. 입력·틱·복귀 시각은 **같은 단조 시간축의 초**여야 한다.

## 정지 분사와 안정화

활성 브러시의 airbrush가 켜져 있거나, PulledString smoothing과 catch-up이 유효하면 `advanceStrokeTime`이 현재 압력·기울기·회전·custom 값을 보존한 채 다음 시각을 진행한다. 안정화는 마지막 필터 위치 대신 보관한 현재 raw target을 사용하여 정지 중에도 따라잡는다. 위치 목록이나 미래 입력은 만들지 않는다.

```cpp
const auto before = editor.revision();
if (editor.advanceStrokeTime(nowSeconds) && editor.revision() != before) {
    // 소비자가 dirtyBounds()를 사용하여 화면을 갱신한다.
}
```

틱 빈도가 분사량을 결정하지 않는다. 획 시작에 한 표본을 찍고, 초당 설정된 비율로 필요한 dab을 방출한다. 같은 시각의 반복 틱은 새 픽셀·리비전을 만들지 않는다. 일반 공간 브러시는 시간만으로 새 물감을 만들지 않으며 이 호출을 거부한다. 종료·취소·Undo/Redo·바인딩 변경 후에는 활성 시계도 없다.

시각은 절댓값 1e12 이하의 유한 값이며 역행할 수 없다. 비유한 값·역행 시각·엔진 이벤트 예산 초과는 false와 lastError로 보고하며 현재 픽셀·리비전·활성 획을 유지한다. 브러시 설정의 시계·따라잡기 값도 preset 검증을 통과해야 한다.

## 전경 상태와 복귀

앱은 포인터 캡처와 전경 상태를 판단한다. 중단 중에는 틱을 전달하지 않는다. 복귀 시 계속할 유효한 획이면 **다음 틱 전에** `rebaseStrokeTime(nowSeconds)`를 호출한다. 캡처나 문서가 유효하지 않으면 기존 `cancelStroke()` 정책을 사용한다.

재기준화는 이전 현재 시각과 새 시각의 차이만큼 시작·다음 분사 시각을 함께 옮긴다. 누적 거리·표본 순서·대칭·마모·색·불투명도 상태는 보존한다. 쉬었던 시간이 논리적인 획 경과 시간이나 다음 속도 계산에 포함되지 않는다. 일반 공간 브러시의 활성 획에도 재기준화할 수 있다.

재기준화 자체는 dab·픽셀·문서 편집·저장 리비전을 만들지 않는다. 시각 1.2에서 중단해 100에 복귀하면 98.8초분의 물감이 생기지 않는다. 복귀 후 100.1의 틱은 추가 0.1초만 처리한다. 앱이 재기준화 없이 큰 시각 차이를 전달하면 엔진은 이를 실제 경과 시간으로 해석한다. SDK는 운영체제의 백그라운드 여부를 추정하지 않는다.

## 파일과 호환성

파일에 바인딩한 편집기도 같은 계약이다. 시각만 재기준화한 작업은 파일 리비전을 늘리지 않으며, 시간으로 그린 픽셀은 기존 획 Undo/Redo와 파일 왕복을 따른다. 기존 좌표·압력 API는 계속 1/120초 호환 시각을 합성한다. 새 시계와 함께 사용할 앱은 실제 입력 경계로 이관하고 시각 원점을 일치시켜야 한다.

공개 객체 배치, ABI 0.33과 IISC 1.22 형식은 유지한다. 소비자는 새 exported target으로 다시 링크해야 새 메서드를 사용할 수 있다.

## 검증

`BitmapClockTest`는 0.2/1/2초의 독립 source-over 분사량, 틱 분할, 미리보기와 release의 동일성, 중단·복귀·역행·비유한 시각·큰 시간 예산 거부, 안정화 따라잡기, 취소와 파일 리비전·Undo/Redo·재열기를 검사한다. 이 검사는 앱의 실제 프레임 틱·전경 전환이나 물리 펜 검증을 대신하지 않는다.
