# 문서 공통 Undo/Redo 이력

iiSharedCanvas Native 0.35.14의 `DocumentHistory`는 하나의 `Document` 또는 열린
`DocumentFile`에 대해 다음 명령을 실제 제출 순서로 기록한다.

- 유한·청크 비트맵 자산 하나에 대한 `replaceBitmapPatches`: 서로 겹치지 않는
  여러 패치를 하나의 원자적 명령으로 처리한다. 일반 페인트와 래스터 마스크는
  각각의 자산 ID로 선택한다. 입력 버퍼는 호출 중에만 빌린다.
- 유한·청크 비트맵에 대한 스트리밍 브러시 획: 현재 입력 표본이나 시계 틱마다
  중간 결과를 반영하고 완료된 획 하나를 공통 이력의 한 명령으로 게시한다.
- 레이어 이름, 표시 여부, 불투명도, 변환, 혼합 모드, 레이어 순서 변경.
- 기존 자산을 참조하는 레이어의 삽입, 프레임별 자산 참조를 포함한 동적 레이어의
  삽입, 레이어의 삭제. 삭제는 레이어와 해당 프레임 키를 제거하고 자산은 남긴다.
- 새 래스터·청크 래스터·벡터 자산과 이를 참조하는 정적 레이어의 결합 삽입.
  Undo는 둘을 제거하고 Redo는 같은 자산 데이터와 레이어를 복원한다.
- 기존 정적 레이어와 다른 레이어가 참조하지 않는 그 자산의 결합 삭제.
- 유리수 프레임 레이트와 전체 프레임 수를 함께 변경하는 타임라인 명령.

예를 들어 페인트 패치, 레이어 이름, 마스크 패치를 차례로 적용하면 세 번의
Undo는 마스크, 이름, 페인트 순서로 실행된다. Redo는 반대 순서이다. 성공한 새
명령은 남은 Redo를 버리고 결과에 그 수를 돌려준다. 값이 바뀌지 않는 명령이나
거부된 명령은 Redo와 커서를 유지한다. `undoLabel`과 `redoLabel`의 문자열 뷰는
다음 변경 호출 또는 이력 소멸 전까지만 보유한다.

```cpp
#include <Document/DocumentHistory.h>

iiSharedCanvas::DocumentHistory history(document);
auto result = history.replaceBitmapPatches("paint", patches, "Paint stroke");
if (result.ok() && result.changed) {
    result = history.setLayerName("layer", "Ink");
}
if (result.ok() && history.canUndo()) {
    result = history.undo();
}
```

파일 바인딩에서는 각 명령과 Undo/Redo가 각자 내구성 있는 파일 트랜잭션이다.
커서는 해당 문서 변경이 성공한 다음에만 이동한다. 0.35.7부터 현재 Native 작업
파일에서 레이어 순서 변경과 그 Undo/Redo는 픽셀 자산 전체 사본을 만들지 않는다.
이전 파일 모델과 저장 형식은 기존 일반 편집 경로를 사용하므로 전체 문서 사본이
생길 수 있다. [파일 레이어 편집](LAYER_FILE_EDITS.md)의 제약을 따른다.
파일을 닫거나 다시 열면 이전 이력은 무효이며 새 이력 객체를 만들어야 한다.

## 문서 타이밍

`setTimeline(Timeline, label)`은 분자·분모로 표현한 프레임 레이트와 프레임 수를
한 리비전과 이력 항목으로 함께 변경한다. 값은 모두 0보다 커야 한다. 기존 프레임
키, 모션 키, 레이어 범위나 오디오 클립이 새 길이에 맞지 않거나, 새 레이트에서
오디오 원본의 필요한 샘플 수가 모자라면 명령 전체를 거부한다. 해당 콘텐츠를
자동으로 자르거나 리타이밍하지 않는다. 프레임 인덱스는 유지되므로 레이트 변경은
그 인덱스가 나타내는 실제 시간을 바꿀 수 있다.

같은 타이밍의 명령은 이력과 리비전을 바꾸지 않는다. 파일 바인딩에서는 이 경우에도
다른 연결의 선행 저장을 확인하며 충돌 시 성공으로 보고하지 않는다. 현재 Native
작업 파일의 실제 변경과 Undo/Redo는 헤더·저작 정보·리비전을 같은 트랜잭션으로
반영한다. 기존 래스터와 오디오 버퍼를 복제하지 않으나 구조·메타데이터 순회와
검증, SQLite와 임시 할당 비용은 남는다. 구형 문서 모델이나 작업 파일은 기존 전체
문서 경로로 마이그레이션할 수 있다. 타임라인 콘텐츠의 자동 조정이나 이력 영속화는
제공하지 않는다.

## 스트리밍 브러시 획

`beginStroke(assetId, brush, sample, label)`로 획을 시작하고
`continueStroke(sample)`과 `endStroke(sample)`으로 현재 표본을 전달한다. 입력은
`StrokePoint`의 위치·압력·단조 시각·기울기·회전·장치 및 사용자 채널을 사용한다.
호출자는 단일 시간축을 유지하며 표본과 브러시는 호출 중에만 빌려준다. 입력 경로
전체나 dab 목록은 보존하지 않고 건드린 픽셀의 원본과 현재 결과만 관리한다.
정지 분사나 안정화 따라잡기는 `advanceStrokeTime(seconds)`, 중단 후 복귀는
`rebaseStrokeTime(seconds)`로 처리한다. 재기준화는 픽셀과 문서 리비전을 바꾸지
않으며 쉬었던 시간의 분사량을 한꺼번에 추가하지 않는다.
이력 객체는 커밋된 획마다 브러시 랜덤 시드를 진행시켜 같은 산포 패턴의 반복을
피한다. 실패·빈 획·취소는 시드를 진행시키지 않으며, 변경된 픽셀을 남기는 명시적
포기는 진행시킨다. Undo/Redo는 저장된 픽셀을 복원하고 다시 난수를 생성하지 않는다.
시드는 이력 객체의 임시 상태이며 문서를 다시 열면 보존되지 않는다.

획이 활성화된 동안 다른 이력 명령과 Undo/Redo, 픽셀 미리보기는 거부되고 기존
Undo·Redo 및 통계는 보존된다. `beginStroke`·`continueStroke`·시간 진행의
`changed`는 해당 호출이 문서 리비전을 바꾸었는지 뜻한다. `endStroke`의 `changed`는
비어 있지 않은 획이 공통 이력에 게시되었는지 뜻한다. 기존 Redo 제거와 선택한
오래된 이력 제거는 성공적인 종료에만 발생하며 결과에 그 수가 표시된다. 캔버스 밖의
빈 획과 실패한 명령은 기존 Redo를 유지한다.

`cancelStroke`는 획이 바꾼 픽셀과 새 청크 존재를 복원하고 기존 이력을 유지한다.
입력 오류·예산 초과·저장 실패는 마지막으로 성공한 중간 결과와 획을 유지하므로
호출자는 오류를 표시하고 재시도하거나 취소해야 한다. 외부 변경과 충돌한 경우
취소는 대상 픽셀을 먼저 검사하고 안전할 때만 복원한다. 대상 변경으로 취소할 수
없다면 `abandonStroke`는 현재 픽셀을 유지하는 대신 모든 공통 Undo·Redo를 버린다.
파일이 닫혀도 명시적 포기는 가능하지만 새 파일 바인딩에는 새 이력 객체가 필요하다.
소유자는 이력 객체를 파괴하기 전에 획을 종료·취소하거나 의도적으로 포기해야 한다.

`strokeStorageBytes`는 건드린 타일의 임시 캐시 논리 크기이고
`strokePendingHistoryBytes`는 잠정 명령 크기이다. 확정된 이력은 `statistics`로
확인한다. 이전 Redo는 획 종료 전까지 보존되므로 임시 캐시와 잠정 명령을 합친
실제 메모리는 확정 이력 한도보다 클 수 있다. `strokeDirtyBounds`는 소비자가
`clearStrokeDirtyBounds`로 지울 때까지 누적되며 종료·취소 뒤에도 남는다. 픽셀
미리보기의 dirty 영역과는 별개이다.

획·확장 획·복합 이력의 할당 실패 회귀는 각각 메모리 검사와 동작별 파일 검사를
별도 CTest로 실행한다. 각 검사는 기존 할당 실패 위치와 문서·이력·파일 보존
단언을 유지한다. 검사 실행 파일을 인자 없이 호출하면 모든 메모리와 파일 검사를
수행한다. `--memory-only`, `--file-only`, `--operation=`을 조합하면 분리된
검사를 직접 실행할 수 있다. 일반 획의 동작 이름은 `begin`, `continue`, `end`,
`cancel`이며 확장 획은 여기에 `undo`, `redo`가 추가된다. 복합 이력의 이름은
`timing`, `timingundo`, `timingredo`, `remove`, `removeundo`, `removeredo`이다.
확장 획의 파일 Undo·Redo는 기존 아홉 실패 위치를 세 그룹으로 나누어 실행한다.
`--file-only --operation=undo|redo --allocation-group=control|lower|upper`로
각 그룹을 선택할 수 있다. 전체 그룹은 기존 위치를 빠짐없이 검사하며 control은
실패와 성공을 모두 확인한다. 그룹 옵션은 지정된 파일 Undo·Redo에만 사용할 수 있다.
동일한 그룹은 독립된 출력 위치를 사용하는 설치 패키지 소비자에서도 검사한다.

파일 바인딩에서는 획 입력과 취소가 각각 동기 트랜잭션이며 다른 리더가 중간
픽셀을 볼 수 있다. 프로세스가 종료·취소 전에 중단되면 마지막으로 저장된 중간
픽셀이 남을 수 있고, 이력은 재열 때 복원되지 않는다. 호출자는 중단 복구 정책을
정해야 한다. 기본 청크 획은 현재 정의된 무한 캔버스 영역 안에서 잘린다.
아래의 명시적 확장 모드를 선택하면 영역과 획을 함께 기록한다. 공통 이력 밖의
영역 변경은 충돌 후 명시적 재기준화가 필요하다. 앱의 입력·시계·문서 이력 채택과 전체 획
기반 테이퍼 작성은 이 API만으로 자동 연결되지 않는다.

## 무한 캔버스 확장 획

`beginStroke(assetId, brush, sample, StrokeCanvasMode::Grow, label)`은 청크형
무한 캔버스에서 실제로 바뀐 픽셀까지 영역을 확장한다. 기존 오버로드와
`StrokeCanvasMode::Clip`은 이전처럼 영역 밖의 픽셀을 잘라낸다. `Grow`를 유한
래스터에 적용하거나 알 수 없는 모드를 전달하면 거부한다. 확장은 기존 영역과
변경 픽셀의 합집합을 청크 경계에 맞추며, 이전에 영역 밖에 있던 청크도 원본
샘플링에 포함한다. 투명하거나 지워진 결과가 원본과 같으면 영역을 늘리거나
Redo를 버리지 않는다. 지원 좌표를 벗어나는 투영이나 표현할 수 없는 영역은
일부 픽셀만 남기지 않고 거부한다.

각 입력은 실제 픽셀, 청크 존재와 영역을 함께 게시한다. 종료 시 한 이력 항목이
생기며 `undo`, `redo`, `cancelStroke`는 픽셀·청크·영역을 함께 복원한다.
진행 중인 획의 후속 입력에서 이력 한도나 저장이 실패하면 마지막 성공 상태와
획을 유지한다. 시작 입력이 실패하면 획이 시작되지 않는다. 확장 획 중 외부
리비전이 바뀌면 다른 자산의 바깥 영역을 숨길 위험이 있으므로 취소를 거부한다.
`abandonStroke`의 이력 폐기 규칙은 기존 획과 같다. 파일 바인딩은 각 중간
입력을 동기적으로 저장하므로 중단 시 최종 입력 이전의 확장 영역과 픽셀이
남을 수 있다. 이력의 영속화나 자동 중단 복구는 제공하지 않는다.

현재 Native 작업 형식에서는 변경된 타일·청크 기술자와 문서 헤더·저작 정보가
하나의 트랜잭션에 속한다. 다른 래스터 전체를 복제하지 않지만 기존 청크 목록의
순회와 전체 문서 구조 검증, 실제 새 청크 할당, SQLite 및 파일 동기화 비용은
남는다. 이전 작업 형식은 첫 실제 변경에서 기존 마이그레이션 경로를 사용하며,
무변경·거부된 획은 형식을 올리지 않는다.

## 레이어의 생성과 삭제

`insertLayerWithAsset(asset, layer, layerIndex, assetIndex, label)`는 새 자산과
정적 레이어를 한 번의 리비전과 이력 항목으로 만든다. 인덱스 기본값은 각각의
목록 끝이다. 자산 ID는 새 ID여야 하고 레이어의 정적 소스 ID와 콘텐츠 종류가 그
자산과 일치해야 한다. 현재 래스터·청크 래스터·벡터를 지원하며 동적 레이어와
비디오 등 다른 자산은 거부한다. 예산·검증·저장 실패는 기존 Undo/Redo와 문서를
보존한다. Undo는 레이어와 자산을 모두 제거한다. 대상 자산이나 레이어가 직접
변경됐거나 다른 레이어·마스크·키가 자산을 참조하면 충돌로 거부한다. Redo는
자산의 픽셀·청크 좌표·벡터 경로와 원래 위치를 복원한다. 자산과 레이어는 값으로
받으므로 호출 전에 인자를 복사하는 동안의 할당 예외는 호출자가 처리한다.

자산 스냅샷은 래스터를 픽셀 원문 또는 무손실 반복 구간 중 더 작은 표현으로
보관하고 벡터 경로와 청크 구조를 보존한다. 압축 결과와 메타데이터는 모두 공통
이력 한도에 포함하며 남은 공간을 넘으면 문서를 바꾸기 전에 `BudgetExceeded`를
반환한다. 입력 래스터와 모든 청크 픽셀의 원본 바이트 합은 별도의
`maximumBitmapInputBytes` 제한도 따른다. 디스크 스필은 없으므로 기본 64 MiB에서 고엔트로피 8K 가져오기는
거부될 수 있다. UI는 이 결과를 사용자에게 표시해야 한다. 임시 입력·복원된 실제
자산·벡터 잉여 용량·할당자·SQLite 메모리와 프로세스 RSS는 이 한도에 포함되지
않는다. Undo의 외부 변경 비교와 Redo의 복원은 대상 픽셀 수에 비례한다.
래스터·벡터 자산이나 경로 명령의 필드·종류를 추가하면 이력의 복원·비교와 보유량
산정도 함께 확장해야 하며, 지원 경로의 구조가 바뀌면 컴파일에서 재검토를 요구한다.

현재 Native 작업 파일은 자산 레코드·새 래스터 타일·레이어·저작 정보와 파일
리비전을 같은 트랜잭션으로 저장한다. 기존 자산의 픽셀·오디오 버퍼는 복제하지
않지만 자산 객체와 레이어·메타데이터 후보를 준비하고 기록 목록과 타일 정보를
조회한다. 성공 후 자산·레이어 객체 참조는 다시 얻어야 한다. 구형 문서나 작업
파일은 기존 전체 문서 경로를 사용할 수 있다. 이력은 파일에 영구 저장되지 않는다.

`removeLayerWithAsset(id, label)`은 기존 정적 레이어와 그 콘텐츠 자산을 한 명령으로
삭제한다. 래스터·청크 래스터·벡터를 지원하며 Undo는 원래 위치와 전체 자산·레이어
데이터를 복원한다. 같은 레이어가 자산을 마스크로도 참조하는 경우 그 레이어와
함께 제거되지만, 다른 레이어의 콘텐츠·마스크·프레임 키가 자산을 참조하면
`Conflict`로 거부한다. 공유 자산을 남기고 레이어만 제거하려면 `removeLayer`를
사용한다. 대상의 지원되는 필드·위치가 외부에서 바뀌었거나 새 참조가 생기면
Redo는 이를 덮어쓰지 않는다. 레이어와 자산의 공개 필드에 대한 모든 직접 수정을
탐지하는 계약은 아니다.

삭제의 자산 스냅샷과 원본 입력 크기도 위 삽입과 같은 이력·비트맵 입력 한도를
따른다. 따라서 디스크 스필이 없는 기본 64 MiB 정책에서 고엔트로피 8K 자산은
삭제 전에 거부될 수 있다. 거부는 문서와 기존 Undo/Redo를 보존하며 소비자는 그
결과를 사용자에게 알려야 한다. 복원에는 실제 자산 크기의 메모리 할당이 필요하다.

`insertLayer(layer, index, label)`는 기존 자산을 참조하는 정적 레이어를 넣는다.
`insertKeyframedLayer(layer, keyframes, index, label)`는 동적 레이어와 프레임별
자산 참조를 한 명령으로 넣는다. 키는 프레임 순서로 정렬되며 중복과 범위 밖의
프레임을 거부하고 프레임 0이 필요하다. 두 명령의 기본 위치는 레이어 목록 끝이다.
`removeLayer(id, label)`는 레이어의 종류·속성·마스크·필터·모션과 모든 프레임 키,
위치를 보존해 Undo에서 복원한다. 참조 대상 자산의 생성이나 삭제는 포함하지 않는다.
`Layer`와 키 목록은 값으로 받으므로 호출자가 값을 복사하는 동안에는 메서드 진입
전에 할당 예외가 발생할 수 있다.

재생 전에 대상 레이어와 키, 원래 위치의 양옆 ID를 확인한다. 직접 필드를 변경해
대상이나 키 또는 그 위치가 달라졌다면 `Conflict`로 거부하고 커서를 유지한다.
공개 필드를 통한 모든 외부 수정을 탐지하는 계약은 아니므로 모든 추적할 편집을
같은 이력 객체에 제출해야 한다. 미리보기 중에는 이 명령을 제출할 수 없다.
메모리 편집의 실패 복구는 레이어 목록과 저작 정보를 후보로 복사하고 동적 레이어는
프레임 구조도 복사한다. 현재 작업 파일은 같은 구조를 트랜잭션으로 저장하며 픽셀과
오디오 자산 전체를 이력에 복사하지 않는다. 구형 파일은 기존 전체 문서 경로를
사용할 수 있다. 성공 후 레이어와 프레임 참조는 다시 얻는다.

## 전체 픽셀 결과의 미리보기

`beginPixelPreview(assetId, label)`로 한 자산의 세션을 시작하고,
`replacePixelPreview`에 이전 결과를 포함하지 않는 **새 전체 결과**를 전달한다.
새 결과에서 빠진 기존 영역은 세션 시작 픽셀로 복원한다. 다시 혼색하지 않도록
작성기는 `pixelPreviewSourceAt`에서 세션 시작 픽셀을 읽을 수 있다. 유한 자산은
자산 내부 좌표, 청크 자산은 문서의 정수 월드 좌표를 사용한다. 호출자가
소유한 입력 궤적을 저장하지 않으며 패치 픽셀을 호출 동안만 빌린다.

미리보기 중 유효한 바인딩에서는 일반 명령, Undo/Redo, `reset`과 또 다른
미리보기를 `PreviewActive`로 거부한다. 외부 변경이나 닫힌 바인딩은 먼저
`Conflict` 또는 `NotBound`를 반환할 수 있다. 기존 Undo·Redo와 그 통계는 보관하되 메뉴에 사용할
`canUndo`와 `canRedo`는 거짓이다. `commitPixelPreview`는 최종 결과가 원본과
다르면 한 명령을 게시하고 이때에만 Redo를 제거하거나 한도 정책에 따라 오래된
Undo를 버린다. 원본과 같은 결과나 취소는 기존 이력을 유지한다. 중첩·부재·
잘못된 패치·자원 한도·충돌 결과를 확인해야 한다. 실패한 교체와 취소는 이전
표시 결과와 미리보기 세션을 보존한다.

교체와 취소의 결과 `changed`는 해당 호출이 문서 리비전을 바꾸었는지 뜻한다.
동일한 결과를 다시 제출하면 최종 이력 데이터가 있어도 `changed`는 거짓이다.
이때 `entryBytes`는 현재 최종 결과의 잠정 명령 크기이다. 확정의 `changed`는
명령을 게시했는지를 뜻하며 확정 자체는 추가 픽셀 리비전을 만들지 않는다.
`previewDirtyBounds()`는 실제 변경 영역의 합집합이며 `clearPreviewDirtyBounds()`로
소비하기 전까지 취소·확정 후에도 남는다. 미리보기 세션을 연속으로 시작해도
아직 소비하지 않은 영역을 지우지 않는다.

세션 소유자는 확정, 취소 또는 의도적인 포기를 **명시적으로 완료한 후** 이력
객체를 파괴해야 한다. 소멸자는 실패할 수 있는 파일 복원을 자동 시도하지 않는다.
메모리 문서의 다른 편집기가 리비전을 바꾼 경우에도 대상 픽셀이 그대로라면
취소할 수 있지만, 기존 이력은 외부 변경과 충돌한 상태로 남는다. `reset`으로
그 이력을 명시적으로 버린 뒤 다시 시작한다. 대상 픽셀이 바뀌면 취소는 복원을
거부하고 재시도 가능한 세션을 보존한다. 복원이 불가능한 경우에만
`abandonPixelPreview`를 호출하면 현재 보이는 픽셀은 그대로 두고 Undo와 Redo를
모두 버린다. 닫히거나 재연결된 파일에서도 세션은 포기할 수 있지만 기존 이력
바인딩은 복구되지 않으며 새 이력 객체가 필요하다.

파일 바인딩 미리보기는 교체·취소마다 독립적인 동기 파일 트랜잭션을 수행한다.
따라서 다른 파일 리더는 미리보기 픽셀을 볼 수 있고, 프로세스가 확정·취소 전에
중단되면 마지막으로 저장된 미리보기 픽셀이 남을 수 있다. 이력은 파일에 저장되지
않으므로 중단 후 자동 복원이나 Undo가 보장되지 않는다. 앱이 복구 정책을 정해야
한다. 이는 미저장 메모리 전용 오버레이나 단일 장기 파일 트랜잭션이 아니다.

`previewStorageBytes`는 임시 원본·표시 타일 캐시의 논리적 크기,
`previewPendingHistoryBytes`는 최종 결과의 잠정 명령 크기이다. `statistics`는
확정된 Undo와 Redo만 포함한다. 기존 Redo는 확정까지 보존되므로 미리보기 중에는
보존된 Redo, 잠정 명령, 임시 캐시의 합이 확정 이력 한도를 초과할 수 있다.
임시 캐시와 입력은 `maximumBitmapInputBytes`, 최종 명령은 전역 이력 예산을
따른다. 이 수치는 할당자와 일시 작업 메모리를 포함한 RSS 상한이 아니다.

## 커밋 전 픽셀 오버레이

`beginStagedPixelPreview(assetId, mode, label)`은 같은 전체 최종 픽셀 교체 계약을
사용하지만 확정 전에는 문서·파일·저작 리비전을 변경하지 않는다. 기본 `Clip`은
기존 자산 범위를 따르고 `Grow`는 청크형 무한 캔버스에만 적용된다. 실제 변경된
픽셀이 기존 영역 밖에 있으면 미리보기 영역을 청크 경계까지 확장한다. 기존
영역 밖의 청크도 원본 픽셀로 읽으며, 원본과 같은 결과는 영역을 확장하지 않는다.

`stagedPixelPreviewTiles()`는 최종 ARGB 픽셀을 64×64 격자에 정렬된 행 우선
타일로 빌려준다. 뷰는
다음 이력 변경 호출 또는 객체 소멸 전까지만 유효하다. 유한 비트맵 타일은
자산 내부 좌표, 청크 타일은 레이어 변환 전의 청크 격자 좌표이며 가장자리
타일은 자산 밖을 포함할 수 있다. 소비자는 결과를 기존 픽셀에 다시 혼합하지
말고 대체값으로 해석해 자산 경계와 레이어 변환을 적용한다. 반환된
`stagedPixelPreviewRegion()`은 확정 시 예상하는 캔버스 영역이며 레이어 변환은
이 계산에 적용하지 않는다.
새 결과에서 빠진 타일은 더 이상 보관하지 않으며 그 위치는 원본 픽셀로 읽는다.
`previewDirtyBounds()`에는 빠진 이전 발자국도 포함하므로 소비자가 그 영역을
다시 그려야 한다. 캐시는 현재 결과의 타일에 비례하며, 미리보기가 지나간 모든
위치를 계속 보관하지 않는다.
호출자는 반환된 타일과 자산 ID를 [프레임 오버레이](FRAME_OVERLAY.md)에 넘겨
동기 렌더에 사용할 수 있다. 애플리케이션 자동 연결은 제공하지 않는다.
오버레이는 입력 경로나 샘플 시퀀스를 보관하지 않는다.

현재 `Grow`의 경계 계산은 변환 전 청크 좌표를 캔버스 좌표로 취급한다. 한 자산이
여러 레이어에 참조될 수도 있으므로 이 API는 어떤 레이어의 변환을 사용할지
자동으로 추측하지 않는다. 이동·회전·스케일된 레이어의 화면상 변경 영역을
확장하는 계약과 앱 연결은 아직 제공하지 않는다. 기본 `Clip`과 픽셀 타일 자체는
자산 좌표에서 동작한다.

교체 결과의 `changed`는 화면상의 오버레이가 바뀌었는지, 확정 결과는 공통 이력
명령이 게시됐는지 뜻한다. 취소의 `changed`는 사라진 미리보기를 다시 그려야
하는지 뜻한다. 확정은 픽셀과 확장 영역을 한 번의 동기 트랜잭션과 이력 항목으로
게시한다. 변경이 없거나 취소하면 파일 리비전과 기존 Redo는 보존한다. 예산·
저장·충돌 오류는 이전 미리보기와 이력을 보존해 재시도 또는 취소할 수 있다.
외부 리비전이나 대상 픽셀이 변경된 경우 확정은 거부한다. 커밋 전 취소는 원본에
쓰기 없이 세션을 해제하므로 외부 편집을 덮어쓰지 않는다. 기존 이력이 외부
리비전과 충돌하면 이후 명시적인 `reset`이 필요하다.

## 소유권, 충돌과 실패

이력 객체는 문서나 파일을 소유하지 않으며 그보다 먼저 소멸해야 한다. 단일
스레드에서 사용하고 기록할 문서 변경을 모두 이 객체로 전달해야 한다. 같은
소유자의 별도 편집기가 리비전을 바꾸면 `Conflict`를 반환하고 커서를 보존한다.
파일은 해당 트랜잭션에서 다른 파일 핸들의 변경도 확인한다. 직접 공개 문서
필드를 수정해 리비전이 변하지 않으면 모든 변경을 감지할 수 없으며, 대상
레이어나 픽셀의 기대값이 달라진 경우에만 덮어쓰기 전에 충돌을 감지한다.
`reset()`은 같은 유효한 소유자의 현 리비전에 다시 맞추면서 Undo와 Redo를
모두 버린다. 외부 변경 충돌로 닫힌 파일은 다시 열고 새 이력을 만들어야 한다.

입력 오류, 이력 한도, 외부 충돌, 자원 부족 또는 파일 오류의 결과를 확인해야
한다. 실패한 명령과 Undo/Redo는 문서와 커서를 함께 보존한다. 바인딩 결과를
확정할 수 없는 외부 파일 충돌은 기존 `DocumentFile` 규칙에 따라 바인딩을
닫을 수 있다. 이때 파일을 다시 열어 결과를 확인한다.

## 예산과 범위

`DocumentHistoryLimits`의 기본값은 64 MiB와 32개 명령이다. `Reject`는 공간이
없으면 실제 변경 전에 거부하고, `EvictOldest`는 필요한 가장 오래된 Undo부터
버린 수를 보고한다. 새 편집이 성공할 경우 버려질 Redo 공간은 사용 가능하다.
한 명령 자체가 상한을 넘으면 어떤 정책에서도 거부한다. 비트맵 입력 패치 수와
입력 바이트도 별도 한도를 따른다. `statistics().retainedBytes`는 Undo와 Redo의
논리적 명령 보유량이다. 명령 객체·이름·자산 ID·편집기 객체와 래스터 저널의
계산된 바이트를 합산한다. 구조 명령은 레이어 속성, 마스크·필터, 프레임 키와
시맨틱 분류의 중첩 문자열과 채워진 배열도 포함한다. 할당자 오버헤드·벡터 잉여 용량·편집기 내부의 모든
동적 관리 객체·일시 작업 메모리·SQLite 또는 프로세스 RSS를 제한하지 않는다.
따라서 이것은 프로세스 전체 메모리의 강제 상한이 아니다.

픽셀 이력은 입력 궤적이 아니라 변경 전후 픽셀과 청크 존재를 보관한다. 이 API는
문서 이력을 저장하거나 다시 열 때 복원하지 않는다. 여러 자산을 한꺼번에 변경하는
단일 명령, 동적 레이어의 새 자산 결합,
비디오 등 지원하지 않는 자산의 결합, 기타 문서 편집, 개별 프레임·모션 키 편집 등
`setTimeline` 외의 타임라인 명령, 애플리케이션의 Undo UI 및 한도 표시는 이 범위 밖이다.
애플리케이션이 기존 개별 편집기 경로를 사용하면 자동으로 이력에 합쳐지지 않는다.

0.35.6부터 참조된 8K 래스터 마스크의 픽셀 편집과 영역 합성을 사용할 수 있다.
필터 전체 처리 비용과 앱의 대형 문서 작업 흐름은 별도이다. 같은 형식의 문서라도
0.35.5 이하의 검증기는 16,777,216픽셀보다 큰 참조 마스크를 거부한다.
[마스크 영역 렌더링](MASK_REGIONS.md)을 참조한다. Native 경로는 Qt를 필요로 하지 않는다.
