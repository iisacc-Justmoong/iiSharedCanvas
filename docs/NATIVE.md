# Qt 없는 문서·편집 패키지

설치본의 이 안내서와 여기에 직접 연결된 문서는 `share/iiSharedCanvasNative/`에
함께 배치된다. 전체 사람용 문서와 대응하는 에이전트 JSON은 그 아래 `docs/`에도
설치된다. 설치 소비자 검사는 이 안내서의 로컬 Markdown 링크를 확인한다.
래스터 샘플링·레이어 합성·마스크·비트맵 이력·픽셀 미리보기의 파일 회귀는
FileProvider가 배타적으로 만든 임시 디렉터리에서 실행되므로, 공통 출력 부모에
이미 존재하는 같은 이름의 파일과 디렉터리를 삭제하지 않는다. 별도 설치 소비자
검사는 기존 파일을 미리 둔 상태에서 이 보존 동작을 확인한다.

네이티브 공개 API는 `Audio/AudioCodec.h`의 제한된 PCM16 WAV 바이트·파일
입출력, `Camera/CameraRaw.h`의 센서 값과 검증, `Render/DocumentPreview.h`의
축소 미리보기도 제공한다. WAV 파일은 기존 네이티브 FileProvider로 게시하며
기존 경로를 덮어쓰지 않는다. 미리보기는 스냅샷이나 작업 파일의 커밋된 내용을
읽고 원본 문서와 리비전을 변경하지 않는다. RAW API는 디코딩된 값의 모델과
검증이며 카메라 제조사 형식의 디코더가 아니다. 자세한 용량과 형식 제한은
각 공개 헤더의 계약을 따른다.

`Vector/SvgExport.h`는 네이티브 경로의 M/L/Q/C/Z 명령과 단색 채우기·획을
SVG 또는 gzip SVGZ로 내보낸다. 경로는 even-odd 채우기와 둥근 획 끝·모서리를
사용하며 색상의 알파와 명령·출력·검증 메모리 한도를 보존한다. 파일 출력은 기본
충돌 거부와 공통 미디어의 IISC·심볼릭 링크 보호를 따른다. 기존 편집 가능한 SVG
가져오기와 SVG/PDF 파일 래스터화는 아직 네이티브 패키지에 포함되지 않는다.
SVGZ 압축은 현재 네이티브 패키지가 직접 사용하는 zlib를 재사용하며, 이 경로의
압축 의존성은 아직 자체 SDK 경계로 옮기지 않았다.

`Vector/PdfExport.h`의 `exportPdf`는 지정된 프레임 범위를 PDF 1.4 페이지로
기록한다. 일반 합성의 벡터 경로와 래스터·청크·비디오 픽셀을 별도로 유지하고
투명 픽셀은 PDF 소프트 마스크로 보존한다. 레이어 불투명도가 1이 아닌 벡터는
독립 그룹 불투명도를 지키기 위해 해당 레이어만 래스터화하고 경고한다. 일반
합성이 아닌 레이어 또는 마스크·필터 등의 외관은 기본적으로 거부하며,
`rasterizeUnsupportedBlending`을 명시하면 해당 프레임을 렌더하여 경고와 함께
기록한다. 대지는 명시적인 대상 선택 기능이 준비될 때까지 거부한다. 페이지의 각
변은 14400pt 이하이며 프레임·벡터 명령·픽셀·출력 한도를 검사한다. 원시 이미지와
출력을 메모리에 구성하므로 큰 PDF에는 출력 크기에 따른 추가 메모리가 필요하다.
`NativePdfExportTest`는 페이지·경로·마스크·명시적 래스터화·한도와 파일 보호를
검사한다. Python과 Poppler 도구가 있는 환경에서는 추가 검사로 PDF를 독립적으로
읽고 벡터와 반투명 래스터의 실제 색상 및 행 순서도 검증한다.

타임라인 교환을 위한 내부 XML 생성기는 표준 C++과 iiSDKCore 숫자 처리로 FCP XML과
FCPXML을 생성한다. 정확한 프레임·오디오 시간, 레이어 순서, UTF-8 이름과 URL,
결합된 출력 바이트 한도를 검사하며 외부 엔터티를 읽지 않는다.
공개 `Timeline/TimelineInterchange.h` API는 이 XML과 PNG·WAV 미디어, 매니페스트,
원본 스냅샷을 새 디렉터리에 게시한다. 레이어 효과·영상·모션 등 보존할 수 없는
내용은 게시 전에 거부한다. iiFileProvider Native 0.11.1 이상의 배타적 디렉터리
게시가 필요하며, 실패 시 기존 대상과 원본을 보존한다. 관련 형식과 제한은
[타임라인 교환](TIMELINE_INTERCHANGE.md)에 있다.
`iisc-export-timeline`은 스냅샷 또는 SQLite 작업 파일을 읽어 같은 패키지를
생성한다. `--name`으로 시퀀스 이름을 지정하고 `--` 뒤에는 대시로 시작하는
경로를 전달할 수 있다. `NativeTimelineXmlWriterTest`와
`NativeTimelineInterchangeTest`는 독립 XML·JSON 파서와 실제 미디어를 사용해
형식, 소스 보존 및 충돌을 검사한다. CLI 테스트와 별도 Python 오라클도 포함한다.

`Video/VideoFrameDecoder.h`는 애플리케이션이 구현한 `VideoFrameDecoder`를 받아
압축 바이트를 `VideoAsset` 또는 동적 비트맵 문서로 바꾸는 경계를 제공한다.
디코더는 표시 방향·정사각 픽셀·고정 프레임 속도로 정규화한 프레임을 공급하고,
캔버스는 요청 범위·프레임 수·픽셀 크기·총량·식별자와 취소를 다시 검사한다.
이 인터페이스 자체에는 코덱이나 파일 읽기 구현이 없으며, 애플리케이션이 자체
SDK를 조합해야 한다. 기존 비디오 코덱 전체를 대체한 것은 아니다. 계약과 제약은
[비디오 프레임 디코더](VIDEO_FRAME_DECODER.md)에 있다.

`Video/VideoFrameEncoder.h`는 앱이 제공한 인코더에 캔버스의 선택된 프레임과
유리수 속도를 전달하며, 결과 크기와 취소를 검사하고 오디오 생략을 경고한다.
앱 소유의 iiVisualCodec 조합 예시는 FFV1 왕복과 다른 코덱의 매트 처리를
지원한다. 메모리 사용과 코덱 범위는 [비디오 프레임 인코더](VIDEO_FRAME_ENCODER.md)를
참조한다.

`Render/AsyncFrameRenderQueue.h`는 애플리케이션이 제공하는 `FrameRenderExecutor`로
프레임 레이어를 병렬 렌더한다. 한 번에 하나의 요청만 실행하고 대기 요청은 가장
최근 요청으로 교체하며, 취소되거나 대체된 결과는 게시하지 않는다. 작업자 수는
실행기의 동시성 힌트, 레이어 수와 최대 64개로 제한한다. 입력은 값 복사 또는
호출자가 변경하지 않는 공유 스냅샷이며, 출력은 `takeCompleted()`로 한 번만
받는다. 아직 가져가지 않은 완료 결과는 새 요청이 실행되는 동안 남으며 다음 완료
결과로 교체되므로 앱은 현재 요청 번호와 비교할 수 있다. 실행기 거절은 별도 결과로
보고하고, 렌더 검증 오류는 기존 렌더 결과에
그대로 담는다. 선택적인 알림은 실행기 스레드에서 잠금 없이 호출되며 취소·소멸과
경합할 수 있으므로 앱이 안전한 수명과 UI 스레드 전달을 관리해야 한다. 실행기는
작업을 한 번만 수락하거나 수락 전에 예외를 던져야 하고, 큐가 살아 있는 동안
수락된 작업을 실행해야 한다. 소멸은 진행 중인 작업을
기다리지 않는다. 이 큐는 표시·입력 위젯이나 기존 Qt 시그널 API를 제공하지 않는다.
소비자는 자체 `iiSDKCore::Runtime`을 `FrameRenderExecutor`에 연결할 수 있다.
`tests/NativeAsyncRuntimeTest.cpp`는 그 결합을 테스트하며 두 SDK를 직접 결합하는
코드는 애플리케이션 쪽에 둔다. 런타임이 대기 작업을 폐기하는 방식으로 종료되기
전에 큐를 먼저 소멸하거나, 작업을 실행하는 drain 방식으로 종료해야 한다.

네이티브 미디어 출력은 대소문자를 구분하지 않고 `.iisc` 경로를 거부한다.
덮어쓰기를 요청한 기존 일반 파일도 앞부분이 IISC 스냅샷이나 SQLite 형식이면
확장자와 관계없이 거부한다. 심볼릭 링크는 출력 대상으로 사용할 수 없다.

네이티브 패키지의 `upgradeIiscFile`과 `iisc-upgrade`는 기존 스냅샷 또는
SQLite 작업 파일의 문서 버전을 현재 버전으로 올린다. 입력 경로만 지정하면
원자적 갱신을 사용하고, 출력 경로를 지정하면 원본을 유지하면서 스냅샷 또는
SQLite라는 저장 종류를 보존한 새 파일을 게시한다. 새 SQLite 출력은 현재 작업
저장 형식으로 생성되므로 입력의 사설 저장 형식 버전까지 동일하지는 않다.
이미 존재하는 출력과 심볼릭 링크 입력은 거부한다. 현재
버전의 제자리 업그레이드는 변경하지 않는다. CLI는 성공 0, 읽기·검증·저장
실패 1, 인자 오류 2를 반환하며 `--` 뒤에는 대시로 시작하는 경로를 받는다.
작업 파일의 커밋된 WAL은 읽기 전용 스냅샷에 반영한다. 세부 계약은
[IISC 업그레이드 CLI](IISC_UPGRADE_CLI.md)를 참조한다.
별도 작업 파일 출력은 충돌을 원자적으로 거부하기 위해 게시 전에 임시 SQLite
파일 전체를 `maximumContainerBytes` 한도 안에서 메모리로 읽는다. 따라서 큰
파일은 그 크기만큼 추가 메모리와 임시 디스크 공간이 필요하다.

기본 설정인 `IISHAREDCANVAS_BUILD_NATIVE_CLI=ON`의 네이티브 `iisc-import`는
지원되는 PSD·OpenRaster 레이어를 새 SQLite 작업
파일로 가져오고, `iisc-export-psd`는 스냅샷 또는 작업 파일의 프레임 0을
PSD로 내보낸다. 두 명령은 Qt 초기화 없이 동작한다. 기존 출력 충돌을 기본으로
거부하고, PSD의 명시적 덮어쓰기는 소스와 같은 파일 또는 그 하드링크·심볼릭
링크를 대상으로 허용하지 않는다. 정확한 지원 형식과 변환 손실은
[가져오기 CLI](LAYERED_IMPORT_CLI.md)와 [PSD 내보내기 CLI](PSD_EXPORT_CLI.md)를
참조한다.

0.35.14는 문서를 수정하지 않는 최종 픽셀 오버레이를 동기 프레임·레이어·타일·
아트보드 영역 렌더에 대체 샘플로 전달한다. 계약과 제한은 [프레임 오버레이](FRAME_OVERLAY.md)에
있다. 애플리케이션 입력 연결과 표시 캐시 무효화는 소비자의 책임이다. 공통 이력 획은
`StrokeCanvasMode::Grow`로 청크형 무한 캔버스를
실제 변경 픽셀에 맞춰 확장할 수 있다. 영역·픽셀·청크의 취소와 Undo/Redo는
한 명령이며 현재 작업 파일은 헤더와 타일을 같은 트랜잭션에 저장한다. 기본
획은 기존과 같이 영역 안에서 잘린다. 범위와 실패 처리는
[문서 공통 이력](DOCUMENT_HISTORY.md)에 있다.

0.35.11은 기존 정적 레이어와 공유되지 않은 래스터·청크 래스터·벡터 자산의
결합 삭제와 프레임 레이트·길이의 원자적 변경을 공통 이력에 추가한다. 다른
레이어가 자산을 참조하면 결합 삭제를 거부하며, 타임라인에 남아 있는 프레임·모션·
오디오가 유효하지 않게 되는 변경은 거부한다. 대용량 SQLite 작업 파일의 스냅샷
백업에는 기본 300초 또는 명시한 양의 밀리초 제한을 사용하며, 디코딩과 검증 전체의
시간 제한은 아니다. 현재 작업 파일의 타임라인 변경은
픽셀·오디오 전체를 복사하지 않고 헤더와 저작 정보를 같은 트랜잭션으로 저장한다.
한도·구형 파일·앱 채택 범위는 [문서 공통 이력](DOCUMENT_HISTORY.md)을 참조한다.

0.35.10은 유한·청크 비트맵의 스트리밍 브러시 획과 시간 진행·재기준화를
문서 공통 이력에 연결한다. 획의 중간 픽셀은 보이되 기존 이력과 Redo는 완료까지
유지하며, 종료는 하나의 명령으로 게시하고 취소는 원본 픽셀을 복원한다.
파일 바인딩은 각 입력과 취소를 동기적으로 저장한다. 수명·충돌·한도와 무한
캔버스 확장의 제한은 [문서 공통 이력](DOCUMENT_HISTORY.md)을 참조한다.

0.35.9는 정적 레이어와 새 래스터·청크 래스터·벡터 자산을 문서 공통 이력의
한 명령으로 함께 만들고 제거·복원한다. 무손실 자산 스냅샷은 이력 예산을 따르며
큰 고엔트로피 이미지는 거부될 수 있다. 메모리·파일 트랜잭션과 나머지 제한은
[문서 공통 이력](DOCUMENT_HISTORY.md)을 참조한다.

0.35.8의 [문서 공통 이력](DOCUMENT_HISTORY.md)은 기존 자산을 참조하는 정적·동적
레이어의 삽입과 삭제를 픽셀·레이어 속성·순서와 같은 Undo/Redo 순서에 기록한다.
레이어 속성과 프레임별 참조를 보존하지만 자산 생성과 레이어 삽입의 결합 명령이나
앱 이력의 자동 전환을 제공하지 않는다.

0.35.7은 현재 Native 작업 파일의 레이어 삽입·키프레임 삽입·삭제·순서를
픽셀 자산 전체 사본 없이 저장한다. 공통 이력의 순서 변경과 Undo/Redo에도 같은
경로가 적용된다. 구조 후보와 파일 트랜잭션, 예전 형식 및 지원하지 않는 이력의
범위는 [파일 레이어 편집](LAYER_FILE_EDITS.md)을 참조한다.

feather 후광으로 처리한다. 작은 영역을 그리기 위해 8K 마스크 전체를 복사하지

자동 수집하지 않으며 지원하는 명령과 파일·메모리 비용의 경계를 확인해야 한다.

[비트맵 영역 편집과 이력](BITMAP_HISTORY.md)에 명시한다. IISC는 1.22 그대로이다.

한 획의 픽셀 누적은 64×64 런타임 타일로 유지하며, 입력 이벤트 사이의 양자화와 불투명도 재적용을 피한다.
편집기 객체의 크기가 바뀌므로 소비자를 재빌드해야 한다. [입력 계약](BITMAP_INPUT.md)을 참조한다.

네이티브 BitmapCodec은 iiImageCodec과 FileProvider를 사용한다. PNG, JPEG, BMP,
TGA, WebP, TIFF를 쓰고 GIF와 PSD의 합성 이미지를 읽는다. 독립 레이어의 PSD는
LayeredDocumentCodec이 담당하며, 한글 레이어 이름, 알파, 27개 혼합 모드를 보존한다.
벡터 출력은 GUI 초기화 없이 PDF 1.4 경로와 알파를 생성하여 PSD Smart Object에 포함한다.

OpenRaster는 메모리 내 ZIP 검증, 제한된 deflate와 CRC, 외부 접근 없는 XML 파싱을
사용한다. 경로 이탈, 링크, 중복 이름, DTD, 과도한 확장 크기를 거부한다. 표현할 수
없는 그룹 합성은 오류이며 중립 pass-through 그룹의 평탄화는 경고이다. 파일 생성과
원자적 교체는 FileProvider가 수행한다. 캔버스는 sRGB 픽셀을 사용하며 지원하지 않는
RGB ICC 프로파일은 iiImageCodec의 네이티브 변환으로 sRGB 작업 공간에 맞춘다.
PSD 입력의 지원 범위를 벗어난 ICC·합성 구성은 명시적으로 거부한다. NativeMedia 테스트는 독립 ORA 픽스처, 손상된
아카이브, 투명 픽셀, 한글 PSD 레이어와 벡터 PDF 포함을 검사한다.

`IISHAREDCANVAS_BUILD_QT_API=OFF`는 Qt 탐색 전에 네이티브 빌드 경로를 선택한다.
설치 소비자는 `find_package(iiSharedCanvasNative CONFIG REQUIRED)`와
`iiSharedCanvas::Native`를 사용한다. 이 패키지의 `Core` 별칭도 같은 네이티브 타깃이다.

기존 표준 C++ 문서·래스터/벡터/타일·편집기·검증·직렬화를 재사용하며,
저자 메타데이터와 SQLite·파일 I/O는 iiFileProvider Native가 소유한다.
문서 파일은 동기 SQLite 트랜잭션과 레코드 검증을 사용한다. 0.35.0의 비트맵 타일·체크섬·마이그레이션은 작업 형식 2 계약을 따른다.
일반 탐색과 렌더링은 저장 리비전을 바꾸지 않는다. 브러시 입력 궤적은 문서에 저장하지 않는다.

`insertChunkedRasterAsset`은 검증한 무한 캔버스 청크 자산을 편집 트랜잭션에 삽입한다.
무한 캔버스의 `renderFrameRegion`과 타일 요청은 저장된 표시 범위 밖의 음수 좌표도
읽을 수 있다. 출력과 좌표 한도를 검사하며 저장된 원점·크기·리비전을 바꾸지 않는다.
유한 캔버스의 요청은 기존 문서 표시 범위 안으로 제한한다.

네이티브와 기존 Qt 패키지는 서로 다른 메타데이터 ABI이다. 하나의 실행 파일에서
두 ABI를 섞어 연결해서는 안 된다. 소비자는 해당 exported target의 정의와 헤더를 함께 사용한다.
기존 Qt 미디어/Quick 어댑터는 명시적인 레거시 패키지로 유지한다.

## 전환이 남은 범위

기본 CMake 옵션과 `install.sh`는 아직 Qt 패키지를 빌드한다. 네이티브 패키지는
아직 기존 패키지의 모든 기능을 대체하지 않는다. 편집 가능한 SVG/SVGZ 가져오기, SVG/PDF
래스터화, 비디오 코덱, Qt Quick 표시·입력·
시그널 어댑터가 남아 있다. 비트맵의 다중 이미지,
텍스트 메타데이터와 일부 확장 포맷도 네이티브 구현에서 기존과 다르다. 기존
동작을 제거하거나 성공으로 보고하지 않고 각 기능의 지원 범위와 손실·오류를
대체 구현 및 테스트에서 확인해야 한다.

현재 네이티브 빌드는 iiPaintEngine, iiFileProvider, iiSDKCore, iiImageCodec뿐
아니라 libxml2와 zlib도 직접 찾는다. Qt가 없는 빌드가 SDK 간 독립성이나
외부 라이브러리 직접 의존성의 제거까지 증명하지는 않는다. 소비자의 Qt ABI와
네이티브 ABI는 다르므로 전환 시 소비자 재빌드 및 앱 소유 브리지가 필요하다.

`iiSharedCanvas.Native.Contracts`는 Qt 없이 생성·편집·거부/예외 롤백·읽기 전용
스냅샷·재열기·저자 메타데이터·직렬화 손상 검사를 실행한다. 설치 소비자도 같은 파일을
exported target만으로 빌드한다. 컴파일 성공과 실제 파일 왕복 결과를 구분하여 기록한다.
파일 영역·작업 타일·레이어 파일 편집·문서 이력 미리보기와 그 할당 회귀의
CTest 시간 제한은 외장 스토리지의 동기 쓰기 대기를 포함한 중단 감지용이며,
편집이나 저장 성능의 목표 시간을 뜻하지 않는다.
단계적 픽셀 미리보기 할당 회귀는 메모리와 파일 실패 지점 전체를 각각 독립된
CTest로 실행한다. 직접 실행할 때 인자가 없으면 두 범위를 모두 검사하고,
`--memory-only` 또는 `--file-only`로 한 범위만 재현할 수 있다.

## 작업 파일과 에이전트 CLI 0.35.0

작업 형식 2는 비트맵 타일·위치별 체크섬과 타일 수를 검증한다. 공개 `readStorageInfo`, `storageVersion`, `upgradeStorage`로 기존 형식 1과 함께 다루며, `iisc-working`은 읽기 전용 inspect/verify, dry-run과 명시적 저장 형식 업그레이드를 JSON으로 제공한다. 현재 네이티브 패키지는 iiFileProvider Native 0.11.1 이상이 필요하다. 세부 계약과 남은 D28 비용은 [WORKING_FILE_TILES](WORKING_FILE_TILES.md)에 있다.

## 링크된 소스 리소스와 테스트 작업 자원

소스 트리의 `resources/`가 워크스페이스 디렉터리에 대한 심볼릭 링크여도 설치본은 링크 대신 실제 리소스 내용을 포함한다. 설치 시 리소스 루트의 실제 경로를 확인하고 내용을 설치 접두 경로의 `share/iiSharedCanvas/resources`에 복사한다. `.iisacc-`로 시작하는 자원 경로는 임시 작업용으로 예약되며 설치본에서 제외한다. `iiSharedCanvas.ResourcesInstall`은 별도의 임시 접두 경로에 설치하고 필요한 리소스의 내용과 경로 독립성을 검사한다. 절대 또는 상위 디렉터리를 포함한 설치 데이터 경로에서는 안전한 임시 설치 검사를 명시적으로 건너뛴다.

Qt 없는 네이티브 빌드에서 `BUILD_TESTING`을 켜면 시험 파일, 임시 설치 접두 경로와 프로세스 임시 파일은 빌드 폴더가 아니라 실제 `resources/` 아래의 예약된 `.iisacc-` 디렉터리에 둔다. 독립 소비자 검사도 같은 경로 계약을 사용하며 설치 패키지의 고정 픽스처는 패키지의 리소스 경로에서 읽는다. `IISC_TEST_WORK_DIR`을 지정하면 이미 존재하는 절대 디렉터리여야 하며, 실제 경로가 자원 루트의 예약된 하위 트리 안에 있어야 한다. 루트 자체, 외부 경로, 없는 디렉터리, 요청 경로 자체가 심볼릭 링크인 경우와 중간 링크가 루트 밖을 가리키는 경우는 거부한다. 지정하지 않으면 구성 시 자원 루트에 고유한 `.iisacc-tests-` 디렉터리를 만들고 그 경로를 CMake 캐시에 보존한다. 자동 생성된 디렉터리를 성공 후 정리한 경우 다음 구성은 새 고유 디렉터리를 만들며, 명시적으로 지정한 누락 경로는 계속 거부한다.

테스트 종료 후 호출자는 자신이 만든 디렉터리의 경로와 소유권을 확인하고 성공한 작업 자원만 정리한다. 실패 자료와 다른 작업의 디렉터리는 보존한다. `iiSharedCanvas.TestWorkDirContract`는 유효한 경로, 별도 CMake 구성 간 기본 디렉터리 정리와 재생성, 자원 루트·외부·미존재 경로 및 가능한 심볼릭 링크 탈출을 검사한다.
